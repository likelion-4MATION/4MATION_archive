# 라우터 파인튜닝 기록 — kf-deberta vs MoAI-Embedding, MoAI 선정 경위

**작성:** 2026-08-06 · 검색/라우팅 트랙
**상태:** MoAI 방향 팀 합의(잠정) — 확정 조건 §6-4 미충족분 진행 중
**관련 문서:** `docs/작업계획서_초기라우팅_B안채택.md` · 1150 테스트셋 생성계획서 · `train_router_kf_deberta.ipynb` / `train_router_moai_embedding.ipynb` (v2)

## 0. TL;DR

HCX 라우팅 콜(평균 1,318ms)을 로컬 분류기로 대체하는 트랙에서 금융 특화 백본 2종을 파인튜닝·비교했다. 승부처인 near-OOD(G5b) AUROC에서 **MoAI-0.6B 0.830(Energy) vs kf-deberta 0.720(MSP), +0.110** — 표본오차(약 ±0.02)의 5배. 단건 추론 지연 65.3ms는 대체 대상의 약 1/20으로, 팀 합의로 **MoAI 방향을 잠정 결정**했다. 이 결정의 실질 비용은 지연 41ms가 아니라 **GPU 상시 서빙 확정**(kf의 CPU 대안 포기)이다.

---

## 1. 배경 — 왜 로컬 라우터인가

- **비용·지연:** 소관밖 질의에도 LLM 콜 1회(평균 1,318ms)가 나간다. 로컬 인코더면 수십 ms.
- **실패 모드:** id19(퇴직연금→근로복지공단 오차단)는 LLM 세계지식 오류였다. 우리 라벨로 학습한 분류기는 그 방식으로 틀리지 않는다.
- **구조는 B안(6업무 분류 + MSP 임계):** OOS 학습 데이터 0건 전제에서, 음성을 직접 학습하는 A안의 open-set 함정(소수 기관 과적합)을 우회하는 선택이었다. 학습 데이터는 `testset_natural_450` 재사용.
- **알려진 사각지대(작업계획서 §5-1):** MSP는 far-OOD(날씨·여권)에 강하고 어휘를 공유하는 near-OOD(금감원·신용회복위 등)에 약하다. 그래서 평가를 G5a(far)/G5b(near)로 쪼갰고, **G5b AUROC를 판정 타이브레이커**로 사전에 못박았다(§5-3).

## 2. 후보 — 왜 이 두 모델인가

라우터 후보는 팀 분담으로 진행했다(타 트랙: ELECTRA 계열). 본 트랙은 **"금융 도메인 사전학습 백본이 near-OOD 분리에 유리할 것"** 이라는 가설로 금융 특화 공개 모델 2종을 맡았다.

| | kf-deberta-base | MoAI-Embedding-0.6B |
|---|---|---|
| 공개 주체 | 카카오뱅크 | BC카드 |
| 구조 | DeBERTa-v2 **인코더** (~186M, bin 746MB) | Qwen3 기반 **디코더**, 임베딩 특화 (0.6B, safetensors 1.19GB) |
| 사전 리스크 | 낮음 (MLM 체크포인트 — 헤드 신규 초기화만) | **로딩 자체가 관문** — 임베딩 전용 구조라 분류 헤드 결합 실패 가능. 실패도 배제 근거로 기록하기로 함 |
| 사전 조건 | — | **채택 bar:** 지연·메모리 열위(GPU 필수)를 정당화할 만큼의 G5b 격차 필요 |

MoAI의 로딩 리스크는 해소됐다 — `Qwen3ForSequenceClassification` 정상 결합, `score` 헤드만 신규 초기화. 디코더 분류는 "pad가 아닌 가장 오른쪽 토큰" 표현을 쓰므로 `config.pad_token_id` 반영이 필수였다.

## 3. 실험 프로토콜 — 그리고 왜 이렇게 바꿨나

### 3-1. 데이터 역할 3분할 (팀 확정)

| 셋 | 역할 | 비고 |
|---|---|---|
| `testset_natural_450` | **학습** — 전량, 분할 없음 | 라벨: business_function(업무명 6) |
| `router_testset_v3_1.jsonl` (1,150) | **dev** — 하이퍼파라미터·체크포인트 채택 전용 | 라벨: domain(D1~D6) + is_oos + group |
| 신규 200건 (예정) | **test** — 최종 1회 | near-OOD 기관은 1150과 비겹침으로 구성 |

### 3-2. v1 노트북의 세 가지 문제 → v2 전환

1. **선택 축 불일치:** v1은 450을 360/90으로 쪼개 val macro_f1로 체크포인트를 자동 선택했다. 승부처는 G5b AUROC인데 다른 축으로 모델을 고르는 구조 — 학습이 진행될수록 과신이 올라가 두 최고점은 대체로 일치하지 않는다.
2. **held-out 소진 함정:** 파라미터를 바꿀 때마다 1150을 열면 그 시점부터 held-out이 아니다(400셋 이중사용·trapset 비분리로 이미 두 번 밟은 함정). 해결은 은폐가 아니라 **역할의 명시적 변경** — 1150을 dev로 승격하고, 정직한 최종 수치는 신규 200 test에 위임했다. 따라서 본 문서의 모든 수치는 dev 수치이며 낙관 편향을 전제한다.
3. **스윕 비용:** EPOCHS를 상수로 두면 에폭 후보마다 재학습이다. v2는 에폭별 체크포인트 8개를 전부 저장(`save_only_model=True`)하고 dev 일괄 평가로 대체 — **학습 1회 = EPOCHS 스윕 8포인트.**

### 3-3. 평가 산식 변경 2건

- **G6(210건) 제외:** G6는 설계상 임계 보정 전용(저신뢰 경계)인데 v1 산식은 이를 음성 풀에 포함해 분리력 지표를 오염시켰다. 양·음성 풀 모두에서 제외하고 별도 집계한다. **이로써 종전 AUROC(타 트랙 ELECTRA 0.708 등)와는 직접 비교 불가** — 본 문서 수치가 새 기준선이다.
- **스코어 2종 병렬(MSP + Energy):** MSP는 softmax 과정에서 logit 절대 크기를 버린다. near-OOD는 "argmax는 확신하되 전체 반응은 약한" 구간이라 그 정보가 유효할 수 있어, 재학습 0회 비용의 Energy(−logsumexp)를 병렬 측정했다. 결과적으로 이 결정이 MoAI의 수치를 결정지었다(§5).

## 4. 지나온 결정·시행착오

| 쟁점 | 선택 | 근거 | 상태 |
|---|---|---|---|
| transformers 버전 | **4.57.6 고정** (4.x 마지막) | 5.x는 `save_safetensors` 제거 등 파손. 두 후보 노트북 버전 통일이 비교 성립 조건 | 확정 |
| accelerate 핀 | 0.33.0 → **>=1.1.0** | 0.33은 `numpy<2` 강제 → 코랩 numpy 다운그레이드 → `numpy.rec` 커널 오류 **실측**. pypi 메타데이터로 원인 확정 후 제거 | 확정 |
| warmup | 0 → **0.1** | 분류 헤드가 랜덤 초기화인데 warmup 없이 최대 LR 진입하던 구멍 | 확정 |
| MoAI 학습 상수 | LR 1e-5 · batch 4 × grad_accum 4 · bf16/fp16 자동 · gradient checkpointing | 0.6B full-FT × 450건에 2e-5는 붕괴 위험. 유효배치 16으로 kf와 LR 의미 일치. T4 메모리 대응 | 확정 |
| 1150을 학습에 쓰는 안(7-class) | 검토 후 **철회** | 데이터 프로토콜 확정(학습=450, 1150=dev)에 따름. B안 구조 유지 | 종결 |
| LoRA vs full-FT 공정성 | 논점 **철회** | 목표가 "모델 우열"이 아니라 "라우팅 적합 모델 확보" — 각 후보를 각자 최적 설정으로 최대화하고 best-vs-best 비교 | 종결 |
| label smoothing 최우선론 | **강등** (후순위 arm 후보) | 과신 완화가 직접 개선하는 것은 ECE(교정)이지 AUROC(순위)가 아님. 순위 보존적 압축은 분리력을 거의 못 움직이고, 표현 클러스터 붕괴로 OOD에 해로울 수 있다는 보고 존재 | 종결 |
| dropout 인자명 | 문서화 | DeBERTa-v2 헤드는 `cls_dropout`(`classifier_dropout` 아님 — config에 조용히 저장돼 print 확인까지 통과하는 거짓양성). 검증은 `model.dropout.p` 모듈 확인으로 | 미실험 |
| Mahalanobis 스코어 | **보류** | §5-4의 후속 후보. 재학습 0회 — kf 쪽 여력 시 A/B | 보류 |
| 라벨 체계 매핑 | **미해결** | 학습 라벨 6종과 dev D1~D6가 6:6 대응이 아님 확인 — D5(파산)·D6(증명서) 대응 라벨 부재, 예금보호 계열은 라벨 2개에 걸침. "D코드→라벨 집합" 매핑 + 미대응 채점 제외 규칙 팀 결정 필요 | **대기** |
| dev 그룹 수량 | 확인 중 | 실측 G5a 80 / G5b 260 / G6 210(내부 is_oos 133) — 생성계획서 §3과 차이. 생성 시 재배분 여부 확인 요청 | 대기 |

## 5. 결과 (seed 42 · dev 1,150 · G6 제외)

| | kf-deberta-base | MoAI-Embedding-0.6B |
|---|---|---|
| 우세 스코어 | **MSP** | **Energy** (전 구간 +0.05) |
| 전체 AUROC | 0.773 | **0.858** |
| **G5b (near — 승부처)** | 0.720 | **0.830** |
| G5a (far) | 0.945 | 0.946 |
| G5a↔G5b 격차 | 0.225 | **0.116** |
| 수렴 | ep4 이후 동률 (0.716~0.720) | ep4 이후 동률 (0.830~0.833) |
| 채택 ckpt (잠정) | checkpoint-203 | checkpoint-232 (116~232 동률 대역) |
| 학습 시간 (232 step, T4) | 58초 | 8분 17초 |

관찰 3건:

1. **스코어 우세가 아키텍처별로 갈렸다** — 인코더(kf)는 MSP, 디코더·임베딩 백본(MoAI)은 Energy. 이후 각 모델은 자기 우세 스코어로 고정하고, 모델 간 비교는 best-vs-best로 한다.
2. **§5-4 예상 시나리오가 실측으로 확정됐다** — kf의 G5a↔G5b 격차 0.225는 계획서가 경고한 "near-OOD 취약 신호" 그 자체다. kf는 전 에폭에서 G5b 0.72 천장에 고착 — 파라미터 스윕의 기대치가 낮다는 신호.
3. **MoAI+Energy가 그 격차를 절반(0.116)으로 줄였다** — near 개선의 큰 레버는 하이퍼파라미터가 아니라 모델·스코어 축이라는 방증(튜닝 가이드 §7의 방향과 일치).

## 6. 왜 MoAI인가 — 선정 근거 (잠정)

판정은 작업계획서 §5-3의 사전 규칙("엇비슷하면 G5b AUROC로 타이브레이크")을 그대로 적용한 결과이며, 세 질문에 수치로 답한다.

**① 분리력 격차가 실질인가 — 그렇다.** G5b +0.110은 AUROC 표본오차(Hanley-McNeil 근사 약 ±0.02)의 5배. 에폭 선택 노이즈로 설명되지 않는다(양쪽 모두 ep4 이후 평평한 대역에서의 비교).

**② 비용이 부담 가능한가 — 그렇다.** 추론 지연 실측(T4 · batch=1 · 토크나이즈 포함):

| | 중앙값 | p95 | 비고 |
|---|---|---|---|
| kf-deberta | 24.2ms | 30.8ms | CPU 서빙 대안 존재 |
| **MoAI-0.6B** | **65.3ms** | **69.5ms** | GPU 서빙 전제 |
| (대체 대상) HCX 라우팅 콜 | ~1,318ms | — | |

MoAI 단건 65.3ms는 대체 대상의 약 1/20이고, 전체 응답시간(검색+생성, 수 초)에서 라우터 비중은 수 % 미만이다. p95가 중앙값에 밀착해 꼬리 위험도 없다. 이를 근거로 팀 합의.

**③ 무엇을 포기하는가 — CPU 서빙 선택지.** 이 결정의 실질 가격은 +41ms가 아니라 **GPU 상시 서빙 확정**이다. kf는 CPU 배포가 현실적 대안이었으나 0.6B는 아니다. PoC 범위에서는 문제없으며, 인프라 논의 시 이 항목이 재론 지점이다.

### 6-4. 확정 조건 (미충족 시 잠정 유지)

1. 시드 3개 평균±표준편차 (§8-3 — 단일 시드 최고값 금지)
2. D코드↔라벨 매핑 결정 → in-scope 정확도 가드레일 측정 (**현재 AUROC 단독으로 선정된 상태**)
3. 채택 스코어가 Energy로 바뀌었으므로 임계(tau)를 Energy 스케일에서 G6로 재보정 (기존 MSP 기반 tau 무효)
4. 신규 200 test 최종 검증

## 7. 알려진 한계 (정직성 기록)

- 본 문서의 성능 수치는 전부 **dev(채택용) 수치** — 이 셋으로 설정을 골랐으므로 낙관 편향을 가진다.
- in-scope 정확도·ECE는 **미측정**(매핑 미확정) — 가드레일이 꺼진 채 AUROC로 선정했다.
- v1→v2는 일괄 전환이라 **항목별 기여도는 분리 측정되지 않았다** (0.830은 묶음 전체의 결과).
- LBR/AOC는 MSP + 자리표시자 tau 기준이라 현재 무효 — 임계 재보정 후에만 유효.
- MoAI 학습의 "bf16" 표기는 T4에서의 비가속 bf16일 가능성이 있다(노트북 메타 gpuType=T4). 학습 시간 비교(×8.6)에는 gradient checkpointing 재계산 비용도 포함되므로 추론 비율로 읽지 말 것 — 추론은 별도 실측(§6-②)이 기준.
