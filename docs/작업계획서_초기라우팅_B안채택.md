# 작업계획서 — 초기 라우팅 모델 (B안: 6업무 분류 + MSP)

**작성 배경:** `routing_model_review.md`(현욱) B안 검토 결과 반영
**대상:** 4MATION — KDIC RAG 챗봇 PoC / 초기 라우팅(업무·업무외·모호) 트랙
**상태:** 계획 초안 — §10 미결정 사항 팀 확인 후 착수

---

## 0. 이 문서의 역할

초기 라우팅을 **HCX 프롬프트 분류 → 로컬 ELECTRA 6분류 + MSP 임계**로 전환하는 작업 계획이다. 평가셋 생성은 별도 문서(`1150_테스트셋_생성계획서`)에서 다루며, 이 문서는 **모델 학습·비교·전환**만 담당한다. 두 문서는 "B안(학습 방법) + 1,150셋(평가)"으로 짝을 이룬다.

---

## 1. 목적

- 라우팅을 교체 가능한 파라미터로 만들어 A/B 대상화한다.
- 비용·지연 절감: 소관밖 질의에 LLM 콜 1회(평균 1,318ms) → 로컬 인코더 수십 ms.
- 실패 모드 개선: id19(퇴직연금→근로복지공단 오차단)는 LLM 세계지식 오류. 우리 라벨 학습 분류기는 그 방식으로 틀리지 않는다.

---

## 2. 접근 방식 확정 — B안 채택

**6대 업무로 학습하고, softmax 최대확률(MSP)이 임계 미만이면 소관밖 판정.**

| | A안 (이진 직접) | **B안 (6분류 + MSP)** |
|---|---|---|
| 음성(OOS) 학습 데이터 | 300~500건 신규 | **0건** |
| open-set 문제 | 정면으로 맞음 (5기관 과적합) | 우회 (음성 미학습) |
| 학습 데이터 | 신규 작성 | **`testset_natural_400` 재사용** |
| 판정 | B안 채택 | ✅ |

**채택 근거:** A안은 음성으로 소수 기관만 보여주면 "소관밖"이 아니라 "그 기관 토픽"을 학습해, 첫 대면 질의(여권·전기요금 등)를 통과시킨다. MSP는 음성을 학습하지 않아 이 함정을 우회한다.

---

## 3. 아키텍처 결정 포인트 — 팀 확인 필수 ⚠️

B안은 **라우팅(MSP in/out)과 도메인 판정(6-class argmax)을 한 모델이 동시에** 수행한다. 그런데 팀은 앞서 "도메인 분류는 별도 모델로 한다"고 정한 바 있다. **이 둘이 충돌하므로 착수 전 확정해야 한다.**

| 옵션 | 구조 | 함의 |
|---|---|---|
| **통합 (B안 그대로)** | 모델 1개가 라우팅+도메인 | 앞단 이진 라우터를 따로 안 둠. 관리 단순 |
| **분리** | 이진 라우터 + 6-class 도메인 분류기 | 모델 2개. B안은 도메인 분류기 자리에만 적용 |

**권고:** 통합(B안)이 데이터·관리 효율에서 우세하나, 도메인 오분류가 라우팅에 전이될 위험이 있다. **결정을 이 문서 착수의 선행조건으로 둔다.**

## 4. 비교 대상 모델 (4종 유지)

| 모델 | 크기 | 비고 |
|---|---|---|
| `monologg/koelectra-base-v3` | 110M | 주 후보 — 의미 태스크(PAWS/KorNLI/KorSTS) 우세 |
| `monologg/koelectra-small-v3` | ~14M | 지연 이점. 6클래스·400건엔 base가 과잉일 수 있음 |
| `beomi/KcELECTRA-base` | 110M | **제외하지 않고 포함** (아래 참조) |
| `snunlp/KR-ELECTRA` / `Dialog-KoELECTRA` | — | 팀 배정 후보 |

**KcELECTRA 포함 근거:** 원 문서는 벤치마크(PAWS −7.95pp, 댓글 코퍼스 미스매치)로 제외를 제안했다. 이 prior는 **타당하나**(PAWS가 착오송금 vs 보이스피싱 최난도 케이스와 닮았다는 지적은 날카롭다), 400건 파인튜닝 후 성능은 사전학습 벤치마크로 확정되지 않는다. 모델 하나 더 돌리는 한계비용이 낮고, "4모델 비교" 원칙 및 문서 §4 단서("채택은 우리 하네스로 판단")와도 일관되므로 **데이터로 확인 후 판단**한다.

## 5. 평가 설계 — 핵심 (near-OOD 분리 측정)

### 5-1. MSP의 사각지대 — 반드시 인지

MSP는 OOS가 in-scope와 **확연히 다를 때**(날씨·여권 = far-OOD) 잘 작동한다. 반면 **어휘를 공유할 때**(금감원·신용회복위·카드/증권 = near-OOD)는 약하다. 6분류기가 이 금융연관 질의에 높은 max-softmax를 뱉을 수 있어 임계로 못 거른다. **이 지점이 팀의 핵심 목표("금융언어와 예금보호 분리, 못 하면 모호로")와 정확히 겹친다.**

### 5-2. 그래서 평가는 두 갈래로 쪼갠다

| 축 | 지표 | 임계치 | 무엇을 보나 |
|---|---|---|---|
| 도메인 분류력 | 홀드아웃 in-scope 6-class 정확도 | 무관(argmax) | 4모델 1차 비교 |
| **OOS 탐지 — 완전무관** | **G5a 대상 AUROC** | 무관 | far-OOD 분리력 (쉬움) |
| **OOS 탐지 — 금융연관** | **G5b 대상 AUROC** | 무관 | **near-OOD 분리력 — 진짜 승부처** |
| 모호 임계 캘리브레이션 | risk-coverage / G6 저신뢰 적중 | 스윕 | 임계 확정 (모델 고른 뒤) |

**정답셋 분할 정의 (중요 — 태그 아님, 그룹 기준):** far/near-OOD 분리는 **`group` 필드로 확정한다** — far-OOD = `group=="G5a"`, near-OOD = `group=="G5b"`. `ambiguity_type=="jurisdiction_boundary"` 태그로 잡지 **않는다**. 태그는 "이 질의가 관할 경계를 건드리는가"라는 **의미 표시**이고, 평가셋 **분할**과는 별개 역할이다. 실제로 G6의 in/out 경계 문항(예: "이게 예보 소관인지 다른 데인지")도 관할 경계를 건드리므로 `jurisdiction_boundary` 태그를 정당하게 가진다. 즉 **G5b가 아니면서 태그가 붙은 항목이 존재하는 것이 정상**이며, 이를 근거로 태그를 떼거나 G5b로 옮기지 말 것. 두 역할을 한 필드에 겸하게 하면 near-OOD 집계가 어긋난다(초기 설계에서 이 혼동으로 88≠80 불일치가 발생했고, 그룹 기준으로 정의하여 해소).

**핵심 규칙:** 4모델 비교는 **임계치 무관 지표(정확도·AUROC)** 로만. 고정 임계 하나로 "모호 몇 건" 같은 수치를 비교에 넣으면 **캘리브레이션 차이를 능력으로 오독**한다. 임계 의존 지표는 모델 확정 후 그 한 모델 안에서만.

### 5-3. 판정 규칙

1. 홀드아웃 도메인 정확도로 줄 세운다.
2. 엇비슷하면 → **G5b AUROC**(금융연관 분리력)로 타이브레이크. 이게 우리 목적의 심장이다.
3. G5a는 다 잘하므로 변별력 낮음. **G5a↔G5b AUROC 격차**가 크면 near-OOD 취약 신호 → §5-4.

### 5-4. G5b AUROC가 낮으면 (예상 시나리오)

순수 MSP 고수를 재고한다. 아키텍처를 갈아엎지 않는 modest한 확장:
- 소량 hard negative를 outlier exposure로 노출
- 인코더 feature 공간 거리 기반 스코어(Mahalanobis 류)를 MSP와 병용

## 6. A/B 계단 — 한꺼번에 넣지 않음 (문서 §6 계승)

기준선: 현행 `hybrid_bf` **hit@3 0.945 / hit@1 0.672 / MRR 0.802**

| # | 변경 | 신규 데이터 | 되돌리기 |
|---|---|---|---|
| 1 | `classify_query_bf` → ELECTRA 6분류 (이진 부스트 유지) | 0 | 함수 교체 |
| 2 | 쿼리측 확률 가중 | 0 | 상수 1줄 |
| 3 | 문서측 확률 부여 + 6차원 내적 | 0 | 필드 추가 |
| 4 | `BF_SHARED_DOCS` 제거 (확률로 자연 표현) | 0 | dict 복원 |
| 5 | 패싯 확률화 | 0 | — |
| — | 라우팅 임계(MSP) 보정·평가 | OOS ~100건 (또는 1,150셋 G5) | 별도 트랙 |

**1~5단계는 신규 라벨 0건.** 임계 보정용 OOS는 이 트랙과 독립.

---

## 7. split 규약 — 측정 오염 방지 (리스크 7-1)

분류기를 400셋으로 학습하고 hit@3도 400셋으로 재면 순환이다. **split을 먼저 긋고 두 숫자를 병기**한다: 베이스라인 연속성용 400 전체 수치 + 홀드아웃 120 정직 수치. 업무 층화(stratified) 유지.

## 8. 리스크 체크리스트 (착수 전·중 확인)

| # | 리스크 | 대응 |
|---|---|---|
| 8-1 | 400셋 이중 사용 순환 | split 선긋기 + 두 수치 병기 (§7) |
| 8-2 | "오분류 0" 상실 | 1단계에서 **오분류 미적중 건수 별도 열**. 0 벗어나면 2단계 진입 전 중단 |
| 8-3 | 시드 분산 | 시드 3~5개 **평균±표준편차** 보고. 단일 시드 최고값 금지 |
| 8-4 | 평가 통계 빈약 | 정상 오거절 근거 6문항 → 0/n 상한 50%. **정상 150건 이상** 필요 (1,150셋이 해결) |
| 8-5 | **near-OOD 취약** | **G5a/G5b AUROC 분리 측정** (§5). 분할은 `group` 기준(태그 아님) |
| 8-6 | 트랩셋 held-out 아님 | `trapset_v0` 개발 노출로 낙관 편향. A/B 판정 근거로 쓰지 말 것 |
| 8-7 | 라우팅으로 안 풀리는 것 | id16(확인형 동조)은 검색·리랭킹 몫. 라우터 교체로 안 고쳐짐 |
