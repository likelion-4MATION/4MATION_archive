### 0-4. 지표 정의 — 이 문서에서 가장 헷갈리는 부분

| 지표 | 정의 | 존재 이유 |
|---|---|---|
| **strict Hit@k** | gold 앵커 스팬을 **원문 그대로 포함한 청크**가 top-k에 있으면 성공 | 재청킹해도 깨지지 않는 엄격 기준 |
| **soft Hit@k** | 위 앵커 청크 **∪ GT가 함께 라벨한 `gt_chunk_ids`**(문항당 평균 1.97개) 중 하나라도 top-k에 있으면 성공 | GT 자신이 relevant로 표시한 청크를 1위로 뽑고도 실패로 세던 문제를 교정(D-1) |
| **nDCG@k** | 앵커 청크=2 / GT 라벨 청크=1 등급으로 계산 | top-k **순서**의 품질 |
| **Hit@30** | 후보 recall 감시용 | 랭킹 개선이 후보 풀을 깎아먹지 않는지 보는 안전장치 |

**A~C·F절은 strict 기준, D~E절은 soft 기준이 주 지표다.** 같은 설정인데 절마다 숫자가 다르면
대개 기준 차이지 실험 차이가 아니다.

### 0-8. 라운드3·4 병행 진행과 최종 결정

E(라운드3)와 F(라운드4)는 **같은 `rag.py`를 서로 모르는 채로 각각 고친 별도 세션**이다.
현재 코드에는 양쪽 변경이 모두 들어가 있고, 두 라운드의 **채택 기준이 달랐다.**

| | E (라운드3) | F (라운드4) | 현재 코드 (E+F) |
|---|---|---|---|
| 채택 기준 | soft Hit@5 최우선, 손실 0 | 악화 0건이면 유의성 미달이어도 채택 | — |
| 변경 | `cap=3` | `cap=3` + 동의어 13항 + 곱셈부스트 | 셋 다 |
| soft Hit@5 | **0.926** | 0.924 | 0.924 |
| soft Hit@1 | 0.605 | **0.612** | 0.612 |
| nDCG@5 | 0.722 | **0.724** | 0.724 |
| strict Hit@1 | 0.516 | **0.522** | 0.522 |

**두 라운드가 독립적으로 `cap=3`에 도달한 것은 상호 검증이다.** 갈리는 지점은 나머지 두 개입
(동의어 13항 · 업무부스트 곱셈화)으로, **soft Hit@5 1문항을 내주고 soft Hit@1 3문항과
nDCG@5 +0.002를 얻는 트레이드**다.

**최종 결정(2026-08-20): 현재 코드(E+F)를 그대로 확정한다.** 목표 지표는 soft Hit@5로 두되
(LLM에 top-5를 넣으므로 Hit@5가 답변 가능 여부를 가른다), 되돌려서 얻는 이득이 **448문항 중
순증 1문항**으로 통계적 유의성이 없어 코드를 되돌릴 근거가 되지 못한다.
즉 **"cap만 쓰는 쪽이 Hit@5가 더 낫다"고 주장하지 않는다** — 0.926과 0.924는 이 평가셋에서
구분 불가한 차이다(Hit@1의 95% CI 폭이 ±4.6pp인 것과 같은 이유).
D-3이 두 개입을 기각했던 근거(유의성 미달)와 F-1이 채택한 근거(악화 0건의 비대칭성)의 충돌은
**F-1의 해석을 채택**하는 것으로 정리한다 — 손실 없는 방향의 변경을 유의성 미달로 되돌릴 이유는 없다.

## A. 실패 원인 분석 — 라운드1

> **기준 주의**: 이 절의 모든 수치는 **라운드1 이전 baseline(strict Hit@1 0.475)** 기준이다.
> D·E 표의 "baseline"은 라운드1 채택 후 설정(0.516)이므로 직접 비교하지 말 것.

448문항 전량의 dense 순위/코사인, BM25 순위/원점수, RRF 성분, bf·facet 부스트를 덤프해 계산했다.
덤프 기반 재현 시뮬레이터가 실제 `search()` 결과를 소수점 셋째자리까지 일치시키는 것을 확인한 뒤 산출한 수치다(추정 없음).

### A-1. 병목은 recall이 아니라 ranking — 결론적

| 항목 | 수치 |
|---|---:|
| **top-30 recall** | **0.989** (448중 443) |
| Hit@1 실패 | 235건 |
| └ 정답 rank 2–3 | **147건 (62.6%)** |
| └ rank 4–5 | 38건 (16.2%) |
| └ rank 6–10 | 31건 (13.2%) |
| └ rank 11–30 | 14건 (6.0%) |
| └ **top-30 밖 (candidate miss)** | **5건 (2.1%)** |

Hit@1 실패의 **97.9%가 이미 후보 안에 정답을 갖고 있다.** 후보 확보는 끝난 문제고, 전부 상위 1~3위 변별 문제다.

### A-2. 실패 6유형 분류 (Hit@1 실패 235건)

| D. Vocabulary mismatch (gold BM25 원점수 0) | 9¹ | 2.0% |

F: 앵커 미보유 0건 · 코퍼스 미수록 앵커 0건으로 v10 앵커 GT는 448건 전량 정상 조인. candidate miss 5건도 육안 확인 결과 GT 오류가 아니라 실제 검색 실패
(예: `nat450-0204 "아이 이름으로 남은 돈 부모가 받나요?"` — gold의 dense rank 59 / BM25 rank 146).

**→ sibling confusion(60%) + 문서 내 청크 변별(29%)이 실패의 89%.**

### A-5. 정답과 1위 오답의 score 마진

rank 2~30 실패 230건 기준 — 중앙값 gap **0.0310**, **gap<0.005 22건 · gap<0.01 43건 · gap<0.02 75건(32.6%)**.
`RRF_K=5`이므로 rank1↔rank2 간격은 `0.6·(1/6−1/7) ≈ 0.014`. **실패의 1/3이 "dense 순위 한 칸 차이"로 뒤집히는 초박빙**이다.

### A-7. freshness 실제 발생 건수

  (facet 발화 문항의 Hit@1이 낮아 보이는 건 그 문항들이 원래 어렵기 때문이며, 제거 A/B가 진실이다.)
- BF_BOOST 제거 → Hit@3 .804→.763 → **기여 중**
- 단일 변수 스윕 결과 `RRF_ALPHA=0.6 / RRF_K=5 / BF_BOOST=0.04 / FACET_BOOST=0.1`은 이미 각자 국소 최적
  (단일 변경 최대 이득 +1.1pp) — **기존 파라미터 재튜닝만으로는 더 짜낼 게 없다.**

### A-9. 진단

정답이 1위가 못 되는 이유는 후보 부족이 아니라, **RRF가 dense의 연속 유사도 마진을 이산 순위로 뭉개서** rank1과 rank2를 가르는 신호를 잃기 때문이다.
실패의 62.6%가 rank 2–3, 32.6%가 gap<0.02에 몰려 있고, dense 1위 28건이 융합 후 1위를 잃는 것이 그 증거다.

0.4~0.75가 평평한 고원이고 채택값이 그 한가운데다. **단일 값만 측정했던 B-2의 공백을 메운 결과,
과적합 우려는 해소된다**(홀짝 교차확인보다 이 곡선이 강한 증거다).

### D-5. `BF_DOC_CAP`은 Hit 기준으로만 no-op이었다 — 등급 기준에선 유의한 이득

코드 주석의 "cap=4와 해제가 완전 동일"은 Hit@1/3/5에서는 참이지만 nDCG에서는 거짓이다.

|---|---:|---:|---:|---:|---:|---|

> ⚠ **E-2에서 갱신** — 목표를 soft Hit@5로 옮기고 실패 문항을 열어보니 문서 중복이 실제
> Hit@5 실패 원인이었다. 위 조건부 권고는 **무조건 채택으로 승격**됐다(cap=3, 개선 3·악화 0).

### D-7. 아직 남은 것 — 이번에도 못 한 두 가지

   실로그 50~100건 검증셋이 필요하다.

## E. 라운드3 — soft Hit@5 최적화 (2026-08-20)

D까지는 Hit@1이 최우선이었다. E는 목표를 **soft Hit@5**로 옮기고, 금지 조건
(**리랭킹·재임베딩·재청킹·아키텍처 변경 금지**) 아래 `data/qscore_cache.npz` 위의
융합/랭킹 항만 탐색했다. 시뮬레이터 파리티는 이번에도 **448/448**.

### E-1. 실패 문항 전수 분석이 먼저다 (soft Hit@5 실패 36건)

`diag_hit5.py`로 36건 전부에 대해 query · gold · dense rank · BM25 rank · 융합 rank ·
top-5 경쟁 청크를 뽑아 분류했다.

| 실패 유형 | 건수 | 비중 |
|---|---:|---:|
| top-30엔 있으나 top-5 밖 | 31 | 86.1% |
| dense/BM25 모두 놓침(둘 다 30위 밖) | 5 | 13.9% |
| dense만 잡고 융합에서 밀림 | 0 | — |
| BM25만 잡고 융합에서 밀림 | 0 | — |
| GT/평가 문제 | 0 | — |

**핵심은 31건의 내용이다.** 상당수가 top-5를 한 문서의 청크로 도배당한 사례였다.

```
nat450-0045 "예보에 잘못 보낸 돈 신청 전에 먼저 거쳐야 하는 절차가 있나요?"
  gold: 착오송금반환지원 신청대상 · dense 3위 · BM25 1위 · 융합 6위
  top5: [반환지원절차] × 4 + [착오송금반환지원 절차]   ← 앞자리를 같은 문서가 막고 있다

nat450-0172 "가지급금이 무슨 돈이에요?"
  gold: 예금보험금이란? · dense 8위 · BM25 9위 · 융합 8위
  top5: [미수령금통합신청 FAQ] × 5              ← 38청크 몬스터 문서가 top-5 전부 점유
```

즉 **동일 문서 중복이 실제 Hit@5 실패 원인으로 확인**됐다. 지시서의 조건부 항목
(`BF_DOC_CAP` 재비교)이 발동한다. D-5의 "Hit 기준 no-op"은 **strict Hit 기준**이었고,
등급·soft 기준으로 다시 재면 성립하지 않는다.

## F. 라운드4 — 동의어 확장 + 업무부스트 곱셈화 (병행 세션 반영본)

> ⚠ **이 절은 E절(라운드3)과 병행해서 진행된 별도 세션의 결과다.**
> 두 라운드가 같은 `rag.py`를 각각 고쳤고, **현재 코드에는 양쪽 변경이 모두 들어가 있다.**
> 채택 기준이 달랐으나(E=soft Hit@5 최우선 / F=악화 0이면 채택) **0-8에서 이 절의 설정을
> 최종으로 확정**했다. E절의 cap 단독 설정이 soft Hit@5에서 1문항 앞서지만 유의하지 않다.

D-3에서 "유의하지 않음"으로 기각했던 두 개입을 **채택으로 뒤집었다.** 근거는 유의성이 아니라 비대칭성이다:
둘 다 **악화 0건**이고(개선 1건 / 2건), 결합해도 서로 잠식하지 않으며(개선 3 / 악화 0), Hit@3·Hit@10·Hit@30을
전혀 건드리지 않는다. n=448에서 3건은 검정력이 없지만, **손실 없는 방향의 변경을 유의성 미달을 이유로
버릴 필요는 없다** — 다만 "+0.6pp 개선했다"고 주장할 수는 없고, 아래 수치는 그 한계와 함께 읽어야 한다.

### F-1. 추가 채택 변경 (`crawler/rag.py`)

| 위치 | 변경 | 근거 |
|---|---|---|
| `QUERY_SYNONYMS` · `expand_query_tokens()` 신설 | 구어→법정용어 13항. **BM25 질의측에만** 확장(치환 아님, 원 토큰 보존) | `아이 이름으로 남은 돈`의 gold가 `예금자가 미성년자인 경우`라 BM25 원점수 0이던 유형 D |
| `Searcher.sparse()` | `tokenize(query)` → `expand_query_tokens(tokenize(query))` 1줄 | 모든 호출자(`hybrid`·`hybrid_soft`·`mode="bm25"`)가 이 한 지점을 지난다 |
| `Searcher.hybrid_soft()` | 업무부스트를 `+boost` → `+boost * dense[idx]/dense_max` | 상수 가산은 같은 업무 청크를 균일하게 올려 형제문서 혼동(실패의 60%)에서 정확히 상쇄된다 |
| `BF_DOC_CAP` | 99 → **3** | D-5. nDCG@5 0.705→0.724. 대가는 Hit@30 0.996→0.980 |

인덱스·청킹·GT·임베딩 여전히 무수정. **인덱스 재빌드 불필요.**
동의어 사전은 실패 실물에서만 뽑았고 질의 ID가 아니라 토큰에 걸리므로 질의별 하드코딩이 아니다.

## G. 종합 — 지금 서 있는 자리와 남은 과제

### G-1. 세 라운드가 남긴 것

| 라운드 | 채택된 것 | 효과 |
|---|---|---|
| 1 (A~C) | `DENSE_W=0.5` · `TITLE_W=0.04` | strict Hit@1 0.475 → 0.516 (McNemar 24/6, **p=0.0014 유의**) |
| 2 (D) | 코드 변경 없음. `eval_anchor_gold.py` 지표 교정 + `eval_fusion_sweep.py` 하네스 | 지표 정의 오류 교정, 미실험 레버 6종 전량 기각 |
| 3 (E) | `BF_DOC_CAP` 99 → 3 | soft Hit@5 0.920 → **0.926** (3/0) · nDCG@5 0.705 → **0.722** |
| 4 (F) | 동의어 13항 + 업무부스트 곱셈화 + `cap=3` (병행 세션) | strict Hit@1 0.516 → **0.522** · nDCG@5 → **0.724** · soft Hit@5 0.924 |

**최종 확정 = 라운드1+3+4가 모두 반영된 현재 코드**(0-8). 목표 지표는 soft Hit@5로 두되,
E의 cap 단독안이 Hit@5에서 1문항 앞서는 것은 유의성이 없어 되돌리지 않는다.

현재 코드는 3·4라운드 변경이 모두 반영된 상태이며, 이것이 **최종 확정본**이다(0-8).

기각된 것도 자산이다 — 재실험 금지 목록: 정규화 fusion(D-3) · 업무부스트 곱셈화(D-3) ·
제목 IDF(D-3) · 동의어 13항(D-3) · 재청킹 188청크(D-3) · `DENSE_W` 추가 튜닝(D-4·E-3) ·
`RRF_K`/`RRF_ALPHA`/`BF_BOOST`/`FACET_BOOST` 재튜닝(B-1·E-3) · cap 조합 튜닝과 `capq`(E-4).
(동의어·업무부스트 곱셈화는 D-3에서 기각됐다가 F-1에서 뒤집혔다 — 금지 목록에서 빠졌다.)

### G-2. 왜 여기서 멈추는가

잔여 실패 33건 중 25건은 **dense와 BM25가 나란히 6~20위**인 문항이다. 두 신호가 동시에 약하면
두 신호를 섞는 식(RRF · 가중치 · 부스트 · 다양성)을 어떻게 조정해도 새 정보가 나오지 않는다.
E-1에서 실제로 잡을 게 있었던 유형("한쪽은 잡았는데 융합에서 밀림")은 cap=3이 전부 흡수해 0건이 됐다.

### G-3. 남은 과제 (우선순위 순)

1. **엔드투엔드(LLM 답변) 평가 부재** — 전 지표가 retrieval-only다. top-k를 실제 LLM에 넣었을 때
   Hit@1/Hit@5 개선이 답변 정확도로 얼마나 옮겨가는지 측정된 적이 없다. 특히 유형 B(같은 문서 내
   다른 청크가 1위, 실패의 29%)는 답변 품질에 거의 무해할 가능성이 높고, 그렇다면 목표 지표
   설정 자체가 재검토 대상이다. 최소 실험: 50문항 × top-3/top-5 컨텍스트 × LLM-judge.
2. **평가셋 편향 미검증** — `span_verbatim_ok`가 448건 **전량 True**(앵커가 청크 원문 그대로)다.
   실사용 질의에서는 이 숫자보다 낮게 나올 수 있어 그대로 배포 기대치로 쓸 수 없다.
   실로그 50~100건 검증셋이 필요하다.
3. **리랭커** — 이번 라운드에서 금지 조건이었다. 도입한다면 top-30 위에 얹고 `BF_DOC_CAP`은
   리랭킹 *이후* 단계로 옮겨야 한다(D-5의 단서).
4. **`고객 미수령금 신청` 단독 최약점**(strict Hit@1 0.347) — 타 업무 혼입이 특이하게 크므로
   `BF_SHARED_DOCS` 재점검이 남은 저비용 후보다.
