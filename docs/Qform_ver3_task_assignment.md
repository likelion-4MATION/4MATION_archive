## §0. 이번 스프린트의 목표와 경계

### 0-1. 목표 — "기능 추가"가 아니라 "막다른 길 제거"

ver2에서 E2E는 관통됐다. 되묻기·슬롯 필터·트레이스가 전부 동작한다.
**남은 문제는 기능 부족이 아니라 대화의 단절이다.**

| 지금 끊기는 지점 | 사용자가 겪는 것 |
|---|---|
| 답변 턴이 끝나면 슬롯이 리셋된다 | 되묻기로 좁힌 결과가 다음 턴에 증발 |
| 응답이 슬롯을 못 채우면 같은 질문 반복 | 대화가 루프에 갇힘 |
| 되묻기 답변을 타이핑해야 한다 | 뭘 입력해야 할지 모름 + 오추출 발생 |
| reject는 고정 문구로 끝난다 | 다음 행동이 없음 |
| 첫 화면이 빈 입력창이다 | 무엇을 물어볼 수 있는지 모름 |

이번 스프린트는 **이 다섯 개를 닫는다.** 새 검색 기능·새 업무·새 모델은 범위 밖이다.

### 0-2. 이번 스프린트의 설계 전제 — 회귀 트리거 0

**검색·생성 동작을 일절 바꾸지 않는다.** 건드리는 층은 두 개뿐이다.

```
전이 층   qform_flow.py · qform_state.py · qform_extract.py   ← 되묻기 판정·슬롯
렌더 층   app.py                                              ← 화면
신규      qform_config.py · qform_followup.py · verify_qform_multiturn.py
```

따라서 **이번 스프린트는 450셋 회귀 측정이 불필요하다.**
R3("숫자 없는 머지는 없다")는 검색·생성 동작 변경에 걸리는 규칙이며, 전이 규칙과 렌더에는 적용되지 않는다.
대신 전이 규칙 변경은 **T4의 결정론 검증(HCX 콜 0)으로 담보한다.**

> 이 문단을 근거로 "수치가 없어서 진행 못 한다"고 멈추지 말 것. 단, **T4를 건너뛰는 것은 금지**다.

### 0-3. 명시적 제외 — 이번에 하지 않는 것

| 항목 | 이유 |
|---|---|
| **응답 스트리밍 / 단계 표시** | `chain.py` 수정 필요. 계약 확장(`on_progress` kwarg)은 **팀 결정 선행**. 이번 범위 밖 |
| 쿼리 부스트 기본 ON | 450셋 회귀 선행 (ver2 §2-4 유지) |
| MoAI 라우터 배선 (G1) | 확정조건 4건 + GPU 서빙 미충족 |
| link route (G4·G9) | HOLES **H7** — 타기관 URL 미확보. 근거 없는 기관명·URL은 창작 |

| 메타데이터 부스트 (G10) | 오라클 실험 선행 |
| B-2 자격·한도 판정 (G6) | R2 정면 충돌 — 의도적 미구현 |

## T1 — 반복질문 버그 해소

### 문제

`reply()`에서 사용자 응답이 어떤 슬롯도 채우지 못하면 상태가 그대로 유지되어 **같은 슬롯을 다시 묻는다.**
원인은 로직이 아니라 **상태 스키마다** — "이 슬롯은 물었고 답을 얻지 못했다"를 기록할 자리가 없다.
`pending_slot`은 현재 묻는 슬롯만 들고 있고, 이력이 없다.

### 작업

1. `qform_state.py` — `new_state()`에 `asked: []` 추가 (물었던 슬롯 이름의 순서 있는 목록)
   - **`SLOT_FIELDS`와 섞지 말 것.** `asked`는 슬롯 값이 아니라 대화 이력이다.
   - `_clean()`이 `asked`를 `answer()`로 흘리지 않는지 확인한다 (부가키 제거 규칙 유지)
2. `qform_flow.reply()` — 응답 반영 후:
   - 슬롯이 채워졌든 아니든 **현재 `pending_slot`을 `asked`에 추가**
   - `ask_turn`을 **무조건 1 증가** (현재는 채워졌을 때만 증가하는 경로가 있는지 확인 후 통일)
3. 다음 질문 선정 시 **`asked`에 있는 슬롯을 후보에서 제외**한다
   - `qform_state.next_question()`에 `exclude: set|None = None` 인자를 추가하는 방식을 기본으로 한다
   - 기존 호출부는 `exclude=None`으로 **동작 완전 동일**해야 한다
4. `asked` 제외 후 물을 슬롯이 없으면 **즉시 답변 턴으로 진행**한다 (`MAX_ASK_TURNS` 도달과 같은 처리)

### 수용 기준 (AC)

| # | 기준 | 측정 |
|---|---|---|
| AC1-1 | 같은 슬롯을 2회 묻는 경우 **0건** | T4 하니스 시나리오 R1~R3 |
| AC1-2 | 응답이 슬롯을 못 채워도 대화가 진행되어 **최대 `MAX_ASK_TURNS`턴 내 답변 도달** | 동일 |
| AC1-3 | `next_question(exclude=None)` 결과가 ver2와 **완전 동일** | 조합 테이블 14행 전수 판정 불일치 **0** |
| AC1-4 | `answer()`로 넘어가는 `qform` dict에 `asked` 키 **미포함** | 반환값 키 검사 |

## T2 — 슬롯 이월 + 대화 정책 파라미터 외부화

### 문제

`start()`가 새 질의마다 `state.update(...)`로 `base_q`·`qform`을 통째로 덮어쓴다.
**턴 간 정보 이월이 0**이라 되묻기로 좁힌 슬롯이 다음 턴에 증발하고, 첨부가 22건으로 복귀한다.

### 설계 — 질의 재작성(LLM)이 아니라 슬롯 이월(상태)로 푼다

LLM 히스토리 주입은 **하지 않는다.** 계약 변경 + 콜 증가 + 측정 불가 3중 비용이다.
Qform 상태가 이미 있으므로 새 인프라 없이 상태 재사용으로 해결한다.

```python
def start(state, query, *, carryover=None, ...):
    prev      = dict(state.get("qform") or {})
    prev_bf   = state.get("bf")
    turn_no   = state.get("turn_no", 0) + 1

    bf    = classify_fn(query) or (prev_bf if <이월 허용> else None)
    slots = extract(query, business_function=bf)

    if <이월 허용> and <스코프 통과>:
        for f in SLOT_FIELDS:
            if slots.get(f) is None and <TTL 유효>:
                slots[f] = prev.get(f)          # 신규 추출이 항상 이긴다
```

**세 가지 불변 조건:**

1. **신규 > 이월.** 새 추출값이 있으면 이월값을 덮지 않는다. → 슬롯 정정("아니 수취인 기준으로")이 자동 처리된다
2. **업무 전환이 방벽.** `bf`가 직전 턴과 다르면 이월하지 않는다 (`CARRYOVER_SCOPE="bf_match"` 기본)
3. **실패는 넓어지는 방향.** 이월이 안 되면 슬롯이 비어 첨부가 넓게 남을 뿐이다. R6·graceful degradation 유지

### 파라미터 외부화 — `chatbot/qform_config.py` (신규)

종합 단계 관리자 콘솔이 읽을 자리를 지금 만든다. **이번 스프린트에서는 기본값 + 사이드바 오버라이드까지만.**

| 파라미터 | 기본값 | 허용값 | 의미 |
|---|---|---|---|
| `SLOT_CARRYOVER` | `True` | bool | 이월 사용 여부 |
| `CARRYOVER_TTL` | `2` | 1~5 | 슬롯이 설정된 후 몇 턴까지 유효한가 |
| `CARRYOVER_SCOPE` | `"bf_match"` | `bf_match` \| `global` \| `off` | 업무 전환 시 정책 |
| `MAX_ASK_TURNS` | `2` | 1~3 | 되묻기 상한 (**기존 `qform_flow` 상수를 여기로 이관**) |

- TTL 판정을 위해 슬롯별 설정 턴을 기록한다: `state["slot_turn"] = {field: turn_no}`
- `MAX_ASK_TURNS` 이관 시 `qform_flow.MAX_ASK_TURNS`는 **하위호환 별칭으로 유지**한다 (기존 import 깨지 말 것)
- `CARRYOVER_SCOPE="global"`은 **데모용 비교 옵션**이다. 기본값으로 승격하지 않는다

### 트레이스

`qform_trace.collect()` 반환에 슬롯별 출처를 추가한다: `신규` / `이월` / `미채움`.
**트레이스를 꺼도 답변·첨부·콜수가 동일해야 한다**(C7 유지).

### 수용 기준 (AC)

| # | 기준 | 측정 |
|---|---|---|
| AC2-1 | 동일 업무 연속 질의에서 직전 확정 슬롯이 유지된다 | T4 시나리오 C1~C2 |
| AC2-2 | **업무 전환 턴의 오이월 0건** | T4 시나리오 C3~C4 (착오송금 → 미수령금 등) |
| AC2-3 | 신규 추출값이 이월값을 항상 덮는다 | T4 시나리오 C5 (슬롯 정정) |
| AC2-4 | `CARRYOVER_TTL` 초과 슬롯은 이월되지 않는다 | T4 시나리오 C6 |
| AC2-5 | `SLOT_CARRYOVER=False`일 때 **ver2와 동작 완전 동일** | T4 회귀 모드 |
| AC2-6 | 후속 턴 첨부 건수가 이월 ON에서 유의하게 좁혀진다 | 시나리오별 첨부 건수 표 (ON/OFF 병기) |

> AC2-6은 성능 주장이 아니라 **동작 확인**이다. 검색을 바꾸지 않았으므로 450셋 회귀 대상이 아니다.
> 단, 리포트에는 **ON/OFF 두 수치를 병기**한다 (R3 정신 유지).

## T3 — 정의형 질의 예외

### 문제

"가지급금이 뭔가요" 같은 **의도 기반 정의 질의**에 되묻기 게이트가 발동한다.
사용자는 개념을 물었는데 신청 절차 슬롯을 채우라고 요구받는다.

### 작업

1. `qform_extract.py`에 정의형 판별을 추가한다 (신규 함수 `is_definitional(query) -> bool`)
2. `qform_flow._step()`에서 정의형이면 **되묻기를 건너뛰고 곧장 `answer()`로 간다**
   - 슬롯은 **추출된 채로 유지**한다. 지우지 않는다 (`skip` 경로와 동일한 취급)
3. 트레이스에 사유 `definitional_bypass`를 남긴다

### 함정 — 패턴을 넓게 잡지 말 것

`제도안내` 어휘는 **"얼마"·"언제까지"·"뭔가요"에 전부 걸린다**(CLAUDE.md §3).
정의형 패턴을 넓게 잡으면 타 업무 질의를 빨아들이고 **스코프 게이트가 무력화된다.**

- **좁게 시작한다.** `~가 뭔가요/뭐예요/무엇인가요/란/이란/의 정의` 수준
- **"얼마"·"언제까지"는 정의형이 아니다.** 포함 금지
- 스코프 게이트(`IN_SCOPE_BF`)는 정의형 경로에서도 **그대로 살아 있어야 한다**

### 수용 기준 (AC)

| # | 기준 | 측정 |
|---|---|---|
| AC3-1 | 정의형 시험 질의(최소 5문항) 되묻기 발동 **0** | T4 시나리오 D1~D5 |
| AC3-2 | 조합 테이블 14행 전수 판정 **불일치 0** | ver2 대비 diff |
| AC3-3 | 소관 밖 정의형 질의는 **여전히 reject** | 스코프 게이트 생존 확인 |
| AC3-4 | "얼마"·"언제까지" 유형이 정의형으로 오판되지 **않음** | 반례 3문항 |

## T4 — 멀티턴 검증 하니스 (신규 파일)

> **이 T를 통과하기 전에 T5로 넘어가지 않는다.**
> T1~T3은 전이 규칙 변경이다. 렌더 작업 중 전이가 깨져도 화면으로는 안 보인다.

### 작업

`chatbot/verify_qform_multiturn.py` 신규 작성. **HCX 콜 0.**

- `classify_fn` · `answer_fn`을 **주입**해 결정론 스텁으로 대체한다 (`qform_flow.start/reply`가 이미 인자로 받는다)
- `verify_qform_e2e.py`의 출력 관행을 따른다 — `전체 통과 ✅` 또는 **어긋난 AC 표**
- 기존 `verify_qform_e2e.py`는 **수정하지 않는다.** 신규 파일로 분리 (§4-5 신규 파일 선호)

## T5 — 되묻기 선택지 버튼 + 예시 질의 칩

### 배경

지금 되묻기 답변은 `st.chat_input` 타이핑으로 받는다. 버튼은 "잘 모르겠어요" 하나뿐이다.
**조합 테이블 생존 행에 선택지 값이 이미 계산돼 있다.** 렌더만 붙이면 세 가지가 동시에 해결된다.

- 사용자가 무엇을 답할지 고민하지 않는다 (룰베이스 챗봇의 유일한 장점 회수)
- **슬롯 오추출이 구조적으로 0** — 값이 enum에서 직접 온다
- **시연이 결정론이 된다** — HCX 비결정성(`temperature 0.2`, seed 없음) 영향을 받지 않는 경로

### 작업

**B1 — 선택지 버튼**

1. 되묻기 턴에서 `qform_state.survivors()` 기반 **생존 값을 버튼으로 렌더**
2. 버튼 클릭 → `qform_flow.reply()`에 **값을 직접 전달** (자연어 추출 경유 금지)
   - `reply(state, text, *, value=None)` 형태로 확장하거나, 값 직접 주입 경로를 별도 함수로 둔다
   - **선택 판단은 어느 쪽이든 좋으나, 값은 반드시 조합 테이블에서만 온다**(C6)
3. 자유 입력(`st.chat_input`)과 "잘 모르겠어요"(`skip`)는 **그대로 유지**
4. 선택지가 6개를 넘으면 상위 6개 + "다른 선택지 보기"로 접는다

**B2 — 예시 질의 칩**

1. 첫 화면(히스토리 비어 있을 때) **6개 칩** — 6업무 각 1개
2. 대화 중에는 사이드바로 이동
3. 칩 문구는 `docs/qform_시험질의셋.md`에서 가져온다. **없으면 만들지 말고 보고한다**

### 함정

- `qform_prompts.csv` **값 수정 금지.** 버튼 라벨은 조합 테이블 값을 그대로 쓴다
- **`subject`는 "대리인 유형"이 아니라 "피대리인 유형"이다**(CLAUDE.md §3). 버튼 라벨을 임의로 다듬지 말 것
- 히스토리 재렌더 충돌 방지: 버튼 `key`에 턴 인덱스 prefix 필수 (기존 `key_prefix` 관행)

### 수용 기준 (AC)

| # | 기준 | 측정 |
|---|---|---|
| AC5-1 | 버튼 경로 슬롯 값이 조합 테이블 값과 **100% 일치** | 14행 대조 |
| AC5-2 | 되묻기 턴 HCX 콜 **0 유지** (ⓐ 모드) | 콜 회계 |
| AC5-3 | 자유 입력·`skip` 경로 **기존 동작 유지** | T4 하니스 재실행 |
| AC5-4 | 첫 화면 칩 6개, 클릭 시 정상 질의 진입 | 수동 확인 |
| AC5-5 | 버튼 라벨에 조합 테이블 밖 문구 **0건** | 문자열 대조 |

## T6 — 슬롯 칩 수정 + reject 복구 경로

### 작업

**B3 — 슬롯 칩 클릭 수정**

지금 `render_slots()`는 채워진 슬롯을 **표시만** 한다. 기획서 §7의 "조용히 반영 금지"는 절반만 지켜진 상태다 — 보이지만 고칠 수 없다.

1. `qform_flow.edit(state, field, value=None)` 신규 — 슬롯 갱신 후 **되묻기 판정 재실행**(`_step`)
   - `value=None`이면 해제
   - 해제 시 `asked`에서도 해당 슬롯을 제거한다 (다시 물을 수 있어야 함)
2. `app.py` — 슬롯 칩에 해제 버튼, 클릭 시 `edit()` 호출 후 `st.rerun()`

**B4 — reject 복구 경로**

1. reject 응답 아래에 **예시 질의 칩 재노출** (T5 B2 자산 재사용)
2. 문구는 "다른 질문을 해보세요" 수준으로 **중립적으로**

### 함정 — 타기관 안내 금지

reject 복구를 만들다 보면 "그건 금감원 소관입니다" 쪽으로 손이 간다. **금지다.**
**HOLES H7이 열려 있어 타기관 URL이 확보되지 않았다.** 근거 없는 기관명·URL은 R2(프롬프트 규칙 1) 위반이며, link route(G4)는 이번 범위 밖이다.

복구 경로는 **"6업무 예시 재노출"** 선에서 끊는다.

### 수용 기준 (AC)

| # | 기준 | 측정 |
|---|---|---|
| AC6-1 | 슬롯 해제 후 되묻기 판정이 **재실행**된다 | 수동 + T4 하니스 |
| AC6-2 | 해제한 슬롯을 **다시 물을 수 있다** (`asked` 정리 확인) | T4 시나리오 추가 |

## T7 — 후속 질문 추천 + 예산·에러 처리

### 작업

**B5 — 후속 질문 추천 (`chatbot/qform_followup.py` 신규)**

답변 후 조합 테이블 **잔여 축**에서 후속 질문 후보를 **결정론으로** 생성한다. **HCX 콜 +0.**

- 생존 행이 좁혀진 상태에서 아직 안 쓴 축(`method`, `sub_task` 등)이 자연스러운 후속 후보다
- 최대 3개. 클릭 시 새 질의로 진입 (이월이 살아 있으므로 슬롯이 유지된다 — T2와 맞물린다)

**함정: 착오송금에서만 뜬다.** 조합 테이블이 14행 = 1업무뿐이다.
다른 업무는 **추천이 안 뜨는 것이 정상**이며 graceful degradation이다.
**커버리지 부족으로 읽고 다른 업무의 조합 행을 창작하지 말 것**(C8 동결).

**B6 — 예산·에러 처리**

1. 사이드바 콜 잔량이 임계 이하면 경고 배너
2. 예산 소진(`call_budget_exhausted`) 시 **대화를 죽이지 않고** 안내 메시지로 처리
3. HCX 실패(`text=None`) 시 `_meta.error`를 사람이 읽을 문구로 변환. **원문 에러·키는 노출 금지**

| AC7-1 | 후속 추천 생성 HCX 콜 **+0** | 콜 회계 |

| AC7-4 | 예산 소진 시 대화 유지, 앱 크래시 **0** | 예산 강제 소진 테스트(콜 0 — 카운터 조작) |
