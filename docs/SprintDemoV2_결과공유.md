## 1. 한 줄 요약

v1이 "플러밍까지, E2E 미착수"로 멈춘 자리를 이어 **큐폼을 실제로 배선**했고, 질의 1건이 **어느 층에서 어떤 근거로 갈렸는지를 우측 패널에 보이게** 했습니다. `rag.py`·`chain.py`를 한 줄도 안 고쳤으므로 **450셋 회귀가 따라오지 않습니다.**

## 2. 무엇이 달라졌나

### 2-1. 이제 실제로 되묻고, 답합니다 (E2E)

v1은 되묻기 로직이 있어도 앱에 물려 있지 않았습니다. 지금은 이렇게 돕니다.

```
질의 → 업무 판정 1회 → 슬롯 추출 → 조합 14행 좁히기
     → 안 좁혀지면 되묻기(최대 2턴)  ← 이 턴에는 답변 생성을 안 부릅니다
     → 좁혀지면 검색·생성 → 첨부를 조합으로 정밀화
```

**되묻기가 콜을 태우지 않습니다.** 2턴을 되물어도 HCX 콜은 분류 1 + 생성 1 = **2콜**입니다.

### 2-2. "하드코딩 티"를 걷어냈습니다 — 그리고 창작 4건을 찾았습니다

v1 되묻기는 고정 문장 2개뿐이었습니다. 문구를 CSV로 빼면서 부연 표현이 **코퍼스에 실제로 있는지** 전수 대조했더니, **4개 전부 0청크**였습니다. 즉 창작이었습니다.

| v1 문구 | 코퍼스 | 지금 |
|---|---|---|
| 비법인단체**(동호회 등)** | **0청크** | 비법인단체를 대리하는 경우 |
| 국외거주·유학생 | 0청크 | 국외거주 또는 유학생을 대리하는 경우 |
| 본인이 **직접 신청** | 0청크 | 본인 |
| 대리인이 **대신 신청** | 0청크 | 대리인 |

대체 문구 `"~를 대리하는 경우"`는 원문 실재라 **근거 청크를 붙였습니다**. 덤으로 문구가 정확해졌습니다 — 2턴째 질문이 "어떤 경우이신가요?"에서 **"누구를 대리해서 신청하시나요?"**로 바뀌었습니다. 원래 묻던 게 *피대리인 유형*이었는데 문구가 그걸 감추고 있었습니다.

### 2-3. 하드코딩 vs LLM을 화면에서 비교할 수 있습니다

되묻기 문구를 **ⓐ 템플릿(콜 0)** / **ⓑ LLM 생성(턴당 1콜)** 토글로 나란히 비교합니다. **어느 쪽이 나은지는 이번에 정하지 않았습니다** — 비교 수단을 만든 것이 목표입니다.

ⓑ에서 LLM은 **문장만 다듬고 선택지는 못 만듭니다.** 조합 테이블 값이 빠지거나 없는 값이 튀어나오면 즉시 ⓐ로 폴백하고 사유를 패널에 남깁니다.

## 3. 실측치

### T1 — 업무 판정 1회 계산·주입

| 항목 | 실측 |
|---|---|
| 450셋 전건 재계산 판정 vs 원본 | **불일치 0** (부스트 변형 82건도 0) |
| 판정 분포 | 확정 322 · 점수미달 123 · 마진미달 5 |
| `extract` 경로 분류 호출 | **1회** (미주입 시 2회 — 가드가 뭅니다) |

### T2 — 되묻기 문구 외부화

| 항목 | 실측 |
|---|---|
| `qform_state.py` 문구 리터럴 | **0개** |
| 14행 되묻기 시뮬 | **0턴 7 / 1턴 1 / 2턴 6 · 평균 0.93턴** (v1과 동일) |

| 선택지 창작 | **0** · 근거 청크 6종 미실재 **0** |

> 아래 두 숫자가 회귀 가드입니다. **문구를 다 갈아엎었는데 판정은 그대로**임을 증명합니다.

|---|---|

| 가드 위반 → 템플릿 폴백 | **8종 전부** (위반 문구 미노출) |
| 두 모드의 되묻기 **판정** | 14행 전수 **불일치 0** |

### T4 — E2E 배선

| 항목 | 실측 |
|---|---|
| 되묻기 2턴 대화 생성 콜 | **1회** (되묻기 턴엔 `answer()` 미호출) |

| 항목 | 실측 |

### 지킨 계약

- `chain.answer()` 반환 **4필드 무변경**
- `crawler/rag.py` · `crawler/eval.py` · `chatbot/chain.py` **diff 0줄** → **회귀 트리거 0**
- 조합 테이블 14행 **동결** · 코퍼스 무수정
- 슬롯이 비면 첨부가 **넓어질 뿐** 좁아지지 않음 (graceful degradation)

## 5. 직접 확인하는 법

```bash
# 업무 판정 재계산 정합 + 트레이스 (T1·T5)
python3 chatbot/qform_trace.py

# 문구 외부화 + 값 고정 가드 (T2·T3) — ⓐ는 LLM 콜 0
python3 chatbot/qform_ask.py

# 회귀 3수치 (문구를 바꿔도 판정 불변)
python3 chatbot/qform_state.py

# E2E 전이 (HCX 콜 0)
python3 chatbot/verify_qform_e2e.py

# 우측 패널 화면 모델
python3 chatbot/qform_panel.py

# 첨부 후단 필터
python3 chatbot/verify_qform_integration.py

# 실제 화면
streamlit run chatbot/app.py
```

### 기대 출력 (숫자가 다르면 뭔가 바뀐 것)

```
qform_state.py    0턴 7행 / 1턴 1행 / 2턴 6행 · 평균 0.93턴 · 발동률 2.0%
qform_trace.py    450셋 불일치 0 · 첨부 필터 전 11서식/24파일
qform_ask.py      문구 리터럴 0개 · 가드 8종 전부 폴백
verify_qform_e2e  104조합 예외 0 · v1 대비 첨부 전건 동일
```

전부 끝에 `전체 통과 ✅` 또는 **어긋난 AC 표**가 뜹니다.

### 눈으로 보고 싶으면

`docs/qform_시험질의셋.md`의 A~G를 순서대로 넣어보시면 됩니다. 특히:

- **C1·C2** — 2번째 질문("누구를 대리해서 신청하시나요?")이 뜨는지. 이게 안 뜨면 법인 대리인이 사업자등록증 안내를 못 받습니다
- **E2·E4** — 타 업무 질의에 큐폼이 개입하지 않는지 (첨부가 사라지면 버그)
- **사이드바 ⓐ/ⓑ 토글** — 같은 되묻기가 문구만 어떻게 달라지는지, 패널의 콜수가 0→1로 바뀌는지

### 확인해 주시면 좋은 것

1. **되묻기 문구가 자연스러운지.** ⓐ와 ⓑ 중 어느 쪽이 나은지 의견 주시면 다음 스프린트에서 기본값을 정하겠습니다
2. **패널에 없어서 답답한 층이 있는지.** 지금 9층인데 더 쪼갤지 합칠지
3. **`국외거주 또는 유학생` 표기** — 코퍼스 원문은 `해외거주자`입니다. 조합 테이블을 원문 표기로 맞출지 (지금은 테이블 동결이라 그대로 뒀습니다)
4. **`ARCH_통합_v0.md` §1만 읽고 흐름이 그려지는지.** 안 그려지면 그 문서가 실패한 겁니다

## 7. 새로 드러난 것 — 부스트를 켜면 업무 판정이 갈립니다

부스트 ON이면 검색 쿼리가 바뀌고, `rag.search`가 **바뀐 쿼리로 업무를 다시 분류**합니다. 슬롯 필터가 보는 업무와 검색 부스트가 보는 업무가 갈릴 수 있습니다.

- 실측 **13건** (450셋, 전부 착오송금). 방향은 검색에 유리한 쪽입니다
- `rag.py` 무수정 제약상 이번 범위 밖이고, **부스트가 기본 OFF라 지금은 안 터집니다**
- 패널은 두 값을 나란히 표기하고 갈리면 `⚠ 업무 갈림`을 세웁니다
- **부스트를 기본 ON으로 올리기 전에 반드시 정리해야 합니다**
