## 1. 한 줄 요약

착오송금 질의를 **자연어 그대로 받아 슬롯으로 채점**하고, 그 슬롯으로 **첨부 양식파일을 좁혀 반환**하는 경로가 동작한다. 검색·생성·반환 계약은 **하나도 건드리지 않았다.**

가장 눈에 띄는 수치 하나 — 구비서류 문서가 검색되면 지금까지 **첨부 22건이 통째로** 나갔는데, 조합 조인을 붙이면 **1~4건**으로 좁혀진다.

---

## 2. 무엇이 달라졌나

### 2-1. 큐폼의 성격이 바뀌었다 (이게 제일 큰 변경)

기획서 v1은 **객관식 폼**을 전제로 쓰였다. 이번에 **자연어 채점**으로 확정하면서 전제 몇 개가 무효가 됐다.

| 기획서 v1 | 변경 | 왜 |
|---|---|---|
| §4 **게이트** (상황설정형이면 큐폼 진입) | **폐기** | 모든 질의에 추출기를 돌리므로 진입/미진입 개념이 없음 |
| §5 순차형 객관식 슬롯 UI | 예시 제시형 되묻기 | 사용자는 자연어로 말한다 |
| §5 확인 화면 **필수** | 되묻기 2턴 발생 시에만 | 평균 0.93턴이라 필수성 약화 |
| §5 "모든 슬롯 건너뛸 수 있다" | **스킵이 디폴트** | 안 말한 슬롯은 자동 `None` |
| R4 게이트 오발동 이탈 | **폐기** → 되묻기 오발동으로 교체 | 게이트가 없어짐 |

즉 큐폼 = **"슬롯 추출기 + 조건부 되묻기"**. 설계스펙 rev.3이 정본이며, 기획서 v1 §4·§5에는 "rev.3이 대체" 주석이 달려 있다.

### 2-2. 되묻기를 언제 하는가 — 오발동을 막는 한 줄

```
sub_task 가 None 이면 → 되묻지 않고 기존 검색 경로로 보낸다
```

이게 핵심이다. "sub_task가 비면 물어보자"로 짜면 *"예금보험공사가 뭐하는 곳인가요"* 같은 단문에 전부 되묻기가 걸린다. 450셋이 전부 단문이라 오발동이 폭발한다.

**되묻기는 `sub_task`가 잡혔는데도 행이 안 좁혀질 때만** 건다. 결과적으로 발동은 `반환신청` 하나에 국한된다.

## 3. 실측치

전부 스크립트 실행 결과다. §5로 직접 재현할 수 있다.

### T1 — 조합 테이블 (14행)

| 항목 | 실측 |
|---|---|
| 행 수 | **14** (경고등 15 아래) |
| 유상 태깅 스키마 허용값 위반 | **0** |
| 근거 앵커 39개 중 미실재 | **0** |
| doc 참조 23개 중 미실재 | **0** |
| 유상 태깅과 조인 | **14/14 성공**, 합계 38건 |
| `outcome` 분포 | `정보` 1 · `서류` 8 · `서류;정보` 5 |

### T2 — 결정론 슬롯 추출기 (LLM 호출 0)

| 슬롯 | 착오송금 84건 | 기타 366건 |
|---|---|---|
| `sub_task` | **74/84 = 88%** | 0% |
| `party` | 64/84 = 76% | 0% |
| `qualification` | 33/84 = 39% | 0% |
| `subject` | 26/84 = 31% | 0% |
| `method` | 29/84 = 35% | 0% |

- 수기 20문항 `sub_task` 정확도 **20/20 (100%)**, 오추출 0 · 미추출 0
- 기타 366건이 전부 0%인 것이 **정상**이다 — 스코프 게이트가 타 업무 질의에 슬롯을 안 채운다. **오추출 억제 지표**로 읽는다

> **왜 정밀도 우선인가** — 오추출은 미추출보다 해롭다. 잘못 뽑힌 슬롯은 정답 조합을 사용자가 보기도 전에 지운다. 하드필터 → 소프트부스트 전환 때 이미 겪은 실패 구조다. 그래서 애매하면 `None`으로 둔다.

### T3 — 조건부 되묻기

| 항목 | 실측 |
|---|---|
| 되묻기 턴 분포 | **0턴 7행 / 1턴 1행 / 2턴 6행** |
| 평균 | **0.93턴** · 최대 2턴 |
| **450셋 발동률** | **9건 / 450 = 2.0%** |
| 착오송금 84건 중 | 9건 = 10.7% |
| `method` 되묻기 | **0회** (설계대로) |
| extract 경유 멀티턴 (AC5) | 2턴 경로 생존 확인 |

발동률 2.0%가 **오발동 지표**다. 450셋은 전부 단문이라 대부분 "폼 불필요"로 나와야 정상이고, 실제로 그렇다.

### B통합 — 첨부 후단 필터

| 시나리오 | 서식 수 | 파일 수 |
|---|---:|---:|
| **필터 없음 (기존 동작)** | **11** | **24** |
| 반환신청·본인 | 3 | 8 |
| 반환신청·대리인·미성년자 | 4 | 10 |
| 반환신청·대리인·법인 | 3 | 8 |
| 반환신청·자격 미상 (7행 생존) | 5 | 12 |
| 신청철회 / 이의제기 / 이체수수료환급 | 각 1 | 각 2 |

실제 질의 예시:

```
"미성년자 착오송금 반환 서류 알려줘요"
  → 신청서양식 · 금융거래정보제공동의서 · 채권양도통지위임장 · 친권합의서   (4건)

"착오송금 반환 신청 철회하고 싶어요"
  → 취소신청서양식                                                    (1건)
```

**부분집합 불변** — 첨부를 새로 추가하지 않고 **좁히기만** 한다. 슬롯이 비면 기존 동작으로 자연히 되돌아간다(graceful degradation).

## 5. 직접 확인하는 법

저장소 루트에서 그대로 붙여넣으면 된다. **네트워크·LLM 호출 없음.**

```bash
# T1 — 조합 테이블 검증
python3 crawler/verify_combos.py

# T2 — 슬롯 추출률 + 수기 20문항 정확도
python3 chatbot/qform_extract.py

# T3 — 되묻기 시뮬레이션 + 450셋 발동률
python3 chatbot/qform_state.py

# B통합 — 첨부 후단 필터 (검색 인덱스 필요, 첫 실행 시 모델 다운로드)
python3 chatbot/verify_qform_integration.py
```

**각 스크립트 끝에 `전체 통과 ✅`가 떠야 한다.** 안 뜨면 어느 AC에서 어긋났는지 표에 표시된다.

### 기대 출력 (숫자가 다르면 뭔가 바뀐 것)

| 스크립트 | 확인할 숫자 |
|---|---|
| `verify_combos.py` | 14행 · 위반 0 · 미실재 0 · 조인 합계 38 |
| `qform_extract.py` | `sub_task` 74/84 (88%) · 수기 20/20 · 기타 366건 전부 0 |
| `qform_state.py` | 0턴 7 / 1턴 1 / 2턴 6 · 평균 0.93턴 · **450셋 발동률 1.3%** |
| `verify_qform_integration.py` | baseline 24건 · 필터 후 1~4서식 · 부분집합 ⊆OK 전항목 |

### 눈으로 보고 싶으면

`chatbot/qform_extract.py`를 열면 맨 아래 수기 20문항이 질의 원문 그대로 있다. 여기에 문장을 추가하고 다시 실행하면 **본인이 던진 질문이 어떤 슬롯으로 채점되는지** 바로 보인다. 오분류를 찾으면 그게 곧 버그 리포트다.

### 확인해 주시면 좋은 것

1. **`sub_task` 오분류** — 88%가 안 잡히는 10건이 무엇인지. 미추출은 정상(검색으로 감), **오추출이면 문제**다
2. **첨부 필터가 너무 좁히는 경우** — 실제로 필요한 서식이 빠지지 않는지. 특히 `반환신청·자격 미상`(5서식)
3. **되묻기 문구** — 지금은 예시 제시형인데 실제 사용자에게 자연스러운지

## 6. 확정된 설계 결정 (rev.3)

| # | 결정 |
|---|---|
| D1 | **게이트 폐기.** 큐폼 = 슬롯 추출기 + 조건부 되묻기 |
| D2 | **되묻기 = 남은 행 ≥ 2.** `sub_task`가 `None`이면 되묻지 않음 |
| D3 | `answer(query, k, qform=None)` — 파라미터만 추가, **반환 4필드 무변경** |
| D4 | `outcome` **다중 부착** (`서류;정보`). 종착점은 배타 분류가 아님 |
| D5 | C02/C03 병합 → **14행**, `combo_id` 재부여 |
| — | 필드명은 **유상 태깅 스키마 기준** (`party`/`sub_task`/`qualification`/`subject`/`method`) |
| — | 근거는 `source_doc_id`(조인) + `evidence_chunks_v0`(검증 힌트) **병기** |
| — | 평가셋 **450건**으로 통일 (기획서 v1의 400은 stale) |

### D4를 다중 부착으로 바꾼 이유

법인·비법인단체·미성년자·군복무자·국외거주 **5행**은 추가서류가 사업자등록증·고유번호증·가족관계증명서·군복무확인서·공관 공증 위임장인데, **전부 외부 기관 발급**이다. 예보가 줄 파일이 없다. 그래서 공통 양식 파일(`서류`)과 발급처 안내(`정보`)가 **동시에** 나가야 한다.

종착점 5종 중 하나를 고르는 구조로는 이 5행이 표현되지 않는다.

### 근거를 문서 단위로 승격하지 않은 이유

스펙 초안은 `#순번`을 버리고 `doc_id`로만 조인하자고 했다. 실제로 해보면 **14행 중 9행이 같은 앵커**가 된다 — 대리인·법인·비법인단체·미성년자·군복무자·국외거주가 전부 `MsdrprPossDcmntGudn` 하나다. 그러면 B-1이 "문서 안 어느 항목인지"를 특정할 근거를 잃는다.

`source_doc_id`(재청킹 불변, 조인용) + `evidence_chunks_v0`(청킹 버전 태그 붙임, 검증용) **병기**로 확정했다.

## 8. 오라클 실험 결과 예측 (미리 읽어두면 좋은 것)

조합 테이블이 **오라클 실험 결과를 사전 예측한다.**

C02~C12 **12행이 `MsdrprPossDcmntGudn` 단일 문서**로 수렴한다. 전체 14행의 86%다.

| 관점 | 함의 |
|---|---|
| **검색** | 슬롯을 뭘로 채우든 같은 문서로 수렴 → **hit@3가 안 움직인다** |
| **답변** | "미성년자면 친권합의서" 같은 항목 선택이 필요 → **B-1의 일** |

즉 오라클 실험이 **+1pp 쪽으로 나올 가능성이 높다.** 그러면 ③ 재태깅 투자는 정당화되지 않는다.

**다만 그래도 발표할 수치가 남는다.** 첨부 **22건 → 1~4건**이 그것이다. hit@3가 안 움직여도 사용자가 받는 결과물은 확연히 달라진다. 큐폼의 값어치가 "검색 순위"가 아니라 **"답변 정밀도"**에 있다는 것이 이번 스프린트의 실측 결론이다.
