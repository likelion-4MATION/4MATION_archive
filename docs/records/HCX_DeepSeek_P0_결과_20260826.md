아니라 생성 모델 비교다.

## 심사 과정에서 확정한 운영 규칙

1. 여러 문항을 한 요청에 넣으면 유사 답변을 병합하거나 객체를 생략할 수 있어, 심사는
   **문항당 독립 세션**으로 실행한다.
2. Judge 모델 ID·reasoning effort·OpenCode 버전·루브릭 해시·입력 해시를 결과마다 기록한다.
3. OpenCode 화면의 진행 모델과 실제 Judge 모델을 구분하고, Judge는 CLI에서 명시적으로 고정한다.
4. 동적 무료 모델은 실험 중 레지스트리에서 사라질 수 있다. `opencode/x-preview-f-free`
   결과는 감사용으로만 보존했고 최종 집계에 섞지 않았다.
5. 모델 또는 루브릭을 바꾸면 이전 Judge 결과와 혼합하지 않고 해당 단계 전체를 다시 심사한다.
6. `key.json`은 전체 심사 검증이 끝날 때까지 열지 않는다.

## 다음 단계

P1은 P0와 독립된 150문항으로 실행한다. 현재 샘플러의 단순 `--n 150` 결과는 P0 40문항 중
37문항과 겹치므로 그대로 쓰지 않는다.

- P0 문항 40개를 P1 후보에서 제외
- 업무 6종 각 20개 이상, AND 25개 이상, 교차업무 10개 이상, 추론형 10개 이상,
  답변불가 2개 전량 포함
- A/B 위치 75:75 균형
- 같은 생성·검색·Judge 계약 유지
- Wilson 95% 신뢰구간·McNemar 검정·생성 3회 비결정성·`answer_checks` 탐지율까지 집계

P1에서 같은 방향의 유의한 차이가 확인되면 비교 실험을 종료한다. P2 450문항 전수는 P1 차이가
사전 정의한 유의 기준 안에서 불명확할 때만 실행한다.
