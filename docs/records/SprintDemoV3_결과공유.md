## §1. 무엇이 닫혔나 ★

ver2 에서 E2E는 이미 관통돼 있었다. 남은 문제는 기능 부족이 아니라 **대화가 끊기는 것**이었다.

| 지금까지 끊기던 지점 | 사용자가 겪던 것 | ver3 | 담보 |
|---|---|---|---|
| 응답이 슬롯을 못 채우면 같은 질문 반복 | 대화가 루프에 갇힘 | **재질문 0건.** 물은 슬롯은 이력에 남겨 후보에서 뺀다 | T4 R1~R3 |
| 답변 턴이 끝나면 슬롯이 리셋 | 되묻기로 좁힌 결과가 다음 턴에 증발 | **슬롯 이월.** 업무가 바뀌면 막는다 | T4 C1~C7 |
| 되묻기 답변을 타이핑해야 함 | 뭘 입력할지 모름 + 오추출 | **선택지 버튼.** 값이 조합 테이블에서 직접 온다 | 14행 전수 대조 |
| 슬롯이 보이지만 고칠 수 없음 | 잘못 잡혀도 손쓸 방법 없음 | **칩 ✕ 해제 → 되묻기 재발동** | T4 E1~E5 |
| reject 는 고정 문구로 끝 | 다음 행동이 없음 | **예시 칩 재노출** | AC6-3·6-4 |
| 첫 화면이 빈 입력창 | 무엇을 물어볼 수 있는지 모름 | **6업무 예시 칩** | 원천 대조 |

### 숫자로

```
되묻기 재질문                0건   (무응답성 대본 4종)
이월 — 동일 업무 후속 첨부    OFF 12건 → ON 8건   (되묻기 1턴도 절약)
이월 — 업무 전환 오이월       0건   (미수령금 · 예금자보호 · 소관밖 3경로)
선택지 버튼 슬롯 값          14행 전수 주입 18회 · 조합 테이블 불일치 0
버튼·추천 라벨 창작          0건
멀티턴 하니스               24/24 통과 · HCX 콜 0
하니스 전체                 11종 전부 초록
```

**HCX 콜은 하나도 늘지 않았다.** 선택지 버튼 0 · 슬롯 해제 0 · 후속 추천 0 · 트레이스 0.
콜을 쓰는 것은 여전히 분류 1 + 생성 1뿐이다.

## §2. 왜 450셋 회귀를 안 돌렸나

**검색·생성 코드를 한 줄도 안 고쳤기 때문이다.**

| 파일 | diff |
|---|---|
| `crawler/rag.py` · `crawler/eval.py` · `chatbot/chain.py` | **0줄** |
| `crawler/data/chunks.jsonl` · `qform_combos_msdr.csv` · `qform_prompts.csv` | **0줄** |

R3("숫자 없는 머지는 없다")는 검색·생성 동작 변경에 걸리는 규칙이고, 이번에 건드린 층은 **전이 규칙과 렌더**뿐이다. 대신 담보를 바꿨다 — `chatbot/verify_qform_multiturn.py` **24시나리오, HCX 콜 0, 재실행 동일 출력**(결과 지문 sha256). 동작 비교가 필요한 항목은 **ON/OFF 두 수치를 병기**했다(첨부 12 vs 8).

## §3. 설계에서 갈렸던 자리

명세서가 비워 뒀거나, 실측이 명세서와 달랐던 곳이다. 전부 근거를 남겼다.

| # | 갈림길 | 택한 것 | 근거 |
|---|---|---|---|
| 1 | 멀티턴을 어떻게 푸나 | **슬롯 이월**(상태 재사용) | 질의 재작성은 계약 변경 + 콜 증가 + `eval.py` 가 단일턴만 재서 **측정 불가** — 3중 비용 |
| 2 | 업무 판정이 불명인 후속 질의 | **직전 업무 상속** | 동일 업무 후속 6문항이 **전부 `classify=None`**. 상속 안 하면 이월이 영영 발동 안 함 |
| 3 | 명세의 `<스코프 통과>` 빈칸 | **신규 추출 슬롯 ≥ 1** | 잡담도 판정 불명이라 방벽을 통과. 실측상 동일 업무 후속은 전부 ≥1, 잡담은 전부 0 |
| 4 | 후속 추천 클릭 | **슬롯 좁히기**(새 질의 아님) | 새 질의로 하면 검색 쿼리가 바뀌어 **부스트 정책을 우회**. 실측 첨부 6 → 0건 |
| 5 | `edit()` 후 답변 | **재생성 안 함 + 명시 버튼** | 칩을 만질 때마다 2콜이면 예산이 샌다 |
| 6 | 정의형 패턴 | **절차·서류 어휘 배제 추가** | 명세 패턴 그대로면 데모 주력 질의(`서류가 뭐예요?`)의 되묻기가 소멸 |

자세한 근거는 `docs/QFORM_ARCH_설계스펙.md` **rev.5 §14~§19**.

## §4. 정직하게 — 성과가 아닌 것

### T3(정의형 예외)은 오늘 고친 버그가 0건이다

명세는 "정의 질의에 되묻기가 발동한다"를 문제로 들었으나 **실측에서 그런 사례가 없었다.**

```
450셋 — 되묻기 발동 9건 ∩ 정의형 어휘 24건 = 교집합 0건
이월 후 다중턴 정의형 후속 9종 — 새로 생긴 되묻기 0건
```

되묻기 게이트가 `sub_task == "반환신청"` 에서만 열리는데 정의형 질의는 `제도안내`/`None` 로 떨어져 게이트가 애초에 안 열린다. **AC3-1이 "발동 0"인 것도 이 기능 덕분이 아니라 원래 0이었기 때문이다.** `is_definitional()` 은 앞으로(6업무 확장 등)를 막는 방어 장치로만 계상한다.

### 후속 추천은 "추천"보다 "필터"에 가깝다

검색 쿼리를 보존하기로 했으므로 클릭해도 **답변 문장은 크게 달라지지 않는다.** 달라지는 것은 첨부의 정밀도다. 회귀 트리거 0을 지키려고 감수한 대가다.

### 예시 칩 6개 중 1개는 원천이 다르다

`고객 미수령금 신청` 만 시험 질의셋에 항목이 없어 450셋 수록 문구를 썼다. 창작은 0이지만 **질의셋의 공백은 그대로 남아 있다**(H28).

### 검증에 실제 HCX 13콜을 썼다

화면 확인이 필요한 지점에서 답변 턴을 태웠다 — T5 2콜(칩 클릭 좌표가 밀려 의도치 않게 답변 턴이 돌았다) · T6 3콜(답변 2 + reject 분류 1) · T7 4콜(답변 2 + 후속 추천 클릭 2) · S7 워크스루 4콜. **그 외 모든 검증은 콜 0이다.** 예산 소진 테스트도 카운터 조작으로 처리했다.

### 시연 경로 초안의 순서가 틀렸다 — 워크스루에서 잡았다

§7의 6단계를 처음엔 `… → 슬롯 해제 → 후속 추천 → 재답변` 순으로 적었는데, **해제하면 되묻기 턴에 들어가고 그 상태에서는 후속 추천이 렌더되지 않아** 다음 단계가 성립하지 않았다. 실기동으로 밟아 보고 나서야 드러났다 — **문서만 쓰고 넘어갔으면 시연 당일에 막혔을 자리다.**

## §5. 의도적으로 하지 않은 것

**이것은 미완이 아니라 판단이다.** 각 항목은 "왜 지금이 아닌가"가 분명하다.

| 항목 | 왜 안 했나 |
|---|---|
| **응답 스트리밍 / 단계 표시** | `chain.py` 계약 확장(`on_progress` kwarg) 필요. 열면 `eval.py`·검증 하니스가 전부 반환값 형태에 의존한다는 사실이 드러난다. **팀 결정 선행** |
| **쿼리 부스트 기본 ON** | 450셋 회귀 수치 미확보 + G13(검색측 이중 분류) 미정리 |
| **MoAI 라우터 배선** (G1) | 확정조건 4건 + GPU 상시 서빙 미충족. 주입점만 유지 |
| **link route** (G4·G9) | HOLES **H7** — 타기관 URL 미확보. 근거 없는 기관명·URL은 창작이다 |
| **6업무 확장** (G11) | 조합 테이블 5업무 미작성. 다른 업무에서 추천·선택지가 **안 뜨는 것이 정상**이다 |
| **메타데이터 부스트** (G10) | 오라클 실험 선행 |
| **B-2 자격·한도 판정** (G6) | 규칙 1 정면 충돌 — **원리적으로 안 한다** |

> **갭 표에서 이번에 닫힌 항목은 0건이다.** G12(관리자 콘솔)만 코드 상태가 한 칸 나아갔다
> (파라미터 4종 외부화 + 사이드바 오버라이드, 콘솔 화면은 없음). 나머지 12개는 그대로 열려 있다.

## §7. 시연할 때

**결정론 영역으로 짜라.** HCX는 seed 없이 `temperature 0.2`라 생성 문장이 시연마다 흔들린다.

| 근거로 써도 되는 것 (결정론) | 쓰지 말 것 |
|---|---|
| 되묻기 문구 ⓐ 템플릿 · **선택지 버튼 값** | 생성 답변 문장 |
| 슬롯 판정 · 생존 행 수 · **이월 사유 문구** | 답변 내 표현·어순 |
| 첨부 목록·건수 · 트레이스 9층 · 콜 회계 | |

### 추천 시연 경로 (총 HCX 4콜) — 08-11 실기동 검증 완료

| # | 조작 | 결과 | 누적 콜 |
|---|---|---|---|
| 1 | 첫 화면 칩 `[착오송금 반환 신청]` | 되묻기 1턴 · 슬롯 2/5 | **0** / 70 |
| 2 | 선택지 버튼 `[대리인]` | 되묻기 2턴 · 슬롯 3/5 · 선택지 6개 | **0** / 70 |
| 3 | 선택지 버튼 `[법인]` | 답변 · 유사도 0.74 · **첨부 6건** | **2** / 70 |
| 4 | 후속 추천 `[접수수단 · 온라인]` | 슬롯 좁히기 → 재답변 버튼 노출 | **2** / 70 |
| 5 | `[이 조건으로 다시 답변받기]` | 답변 · 슬롯 **5/5** · 유사도 0.74 · **첨부 6건 유지** | **4** / 70 |
| 6 | 슬롯 칩 `[주체 법인 ✕]` | 되묻기 재발동 · 선택지 6개 복구 | **4** / 70 |

**1·2·4·6이 전부 콜 0**이다. 트레이스 패널의 `HCX 0콜 = 게이트 0 + 되묻기 0 + 생성 0` 배지로 보여주면 된다.

> **순서가 중요하다 — 슬롯 해제는 맨 뒤에 둔다.**
> 해제하면 되묻기 턴으로 들어가는데, **되묻기 중에는 후속 추천과 슬롯 칩이 렌더되지 않는다**
> (지금 물어보고 있는 것에 답하는 게 먼저다). 해제를 중간에 넣으면 그다음 후속 추천 단계가
> 성립하지 않는다. 초안에 이 순서로 적었다가 워크스루에서 잡았다.

**5번이 이 데모의 핵심이다.** 후속 추천을 "새 질의"로 만들었을 때는 검색 쿼리가 바뀌어 첨부가
6건 → **0건**으로 무너졌다(§3 갈림길 4). 슬롯 좁히기로 바꾼 지금은 유사도·첨부가 그대로 유지된다.

체크포인트는 "**되묻기 2턴이 콜 0**", "슬롯 5/5까지 채우는 동안 추가 콜 0", "9층 중 6층이 콜 0",
"어느 화면에서도 다음 행동이 있다".

python3 chatbot/verify_qform_multiturn.py   # 멀티턴 24시나리오 (핵심)

전부 `전체 통과 ✅` 또는 어긋난 AC 표를 낸다. **11종 전부 초록**이며 `verify_qform_multiturn.py` 는
재실행 시 같은 결과 지문(sha256)을 낸다.

### `verify_qform_e2e.py` AC2 를 고친 것에 대해

무변경 목록 파일이지만 **사람 승인을 받아 기대값 3줄을 개정**했다. AC2가 ver2의 "같은 슬롯 재질문"을 기대값으로 박아 두고 있어 T1(재질문 차단)과 **충족 불가**였기 때문이다. AC가 지키려던 성질은 그대로이고 2턴 → 1턴으로 오히려 강해졌으며, 같은 성질을 멀티턴 하니스 R2가 겹쳐 잰다. 자세한 것은 `DECISIONS.md` D9.
