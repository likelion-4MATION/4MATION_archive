### 0-3. 충돌면은 좁다 — 그러나 의미 병합이 위험하다

ver3 기준으로 `feature/anc`와 동시에 건드린 파일은 **`DECISIONS.md` 하나**였다.
`feature/anc`는 `chatbot/`을 건드리지 않았고, Qform 트랙은 `crawler/rag.py`를 건드리지 않았다.
ver4도 같은 성질일 것으로 예상하나 **M-1에서 재확인한다.**

`chatbot/`은 `sys.path`로 `crawler/rag.py`를 **무수정 소비**한다. 그 rag.py가 anc에서 바뀌었다.

| 항목 | ver3 (챗봇이 검증한 값) | anc (새 값) |
|---|---|---|
| 코퍼스 | 215청크 | **181청크** (표 원자성 수정) |
| RRF_ALPHA | 0.6 | 0.65 |
| RRF_K | 5 | **4** |
| BF_BOOST | 0.005 | **0.06** (12배) |
| FACET_BOOST | 0.03 | 0.05 |
| BF 분류 | 키워드 | **MOAI 라우터** (모델 부재 시 키워드 폴백) |
| 임베딩 모델 | `dragonkue/BGE-m3-ko` | 동일 (재임베딩은 코퍼스 변경 때문) |

`rag.py` 주석이 직접 경고한다 — *"이 값들은 181청크 코퍼스와 한 세트다.
옛 청킹(215)에서 RRF_K=4를 쓰면…"*.
→ **코퍼스·인덱스·파라미터는 원자 교체다. 부분 이전은 성능이 무너진다.**

### 0-4. 🔴 두 트랙이 만나는 순간 조합 테이블 근거가 끊어진다

`qform_combos_msdr.csv`와 `verify_combos.py`는 **Qform 트랙에만** 있고(`feature/anc`·`dev`에 없음),
재청킹은 **anc 트랙에서만** 일어났다. **두 파일이 한 번도 만난 적이 없어서 아무도 안 깨졌다.**
병합이 그 만남이다.

| 기준 | 총 청크 | `MsdrprPossDcmntGudn` | `MsdrprAttnMttr` |
|---|---:|---|---|
| ver3 / dev | 215 | **20개** (#00~#19) | 8개 |
| **feature/anc** | **181** | **2개** (#00, #01) | **3개** |

**MSDR 14행 중 C03~C12 10행은 근거 청크가 하나도 안 남고, C02는 절반이 날아간다.**
(C01·C13·C14만 생존)

"FAISS 적재 수 = 청크 수 일치" 검사는 **이걸 통과시킨다.** dangling 참조는 개수 대조로 잡히지 않는다.
`QFORM_ARCH` §5가 설계해둔 "정합 체크 diff"가 정확히 이 용도인데, 실존 검사가 없으면
**그 검증은 지금 아무것도 보증하지 않는다.**

**DPIN 9행이 더 큰 미지수다** — 215 기준으로 박혔으면 폭탄이 두 배, 181 기준이면
MSDR과 DPIN이 서로 다른 코퍼스를 참조하는 상태가 된다. M-1에서 확인한다.

### 0-5. 설정 정본은 이미 존재 — 새 파일 만들지 않는다

`admin/registry.py`가 파라미터 정본이다. `_p(key, label, type, default, tier, apply, source, help)`
행으로 선언되고, `tier`(normal/advanced/rebuild/locked)·`apply`(runtime/rebuild)로
**"바꾸면 인덱스를 다시 만들어야 하는 값"까지 구분**돼 있다. `settings.effective()`가
override+pending을 병합해 내보낸다.

```python
_p("k",          "답변에 참고할 문서 수", "int",   3,    "normal",   "runtime", ...)
_p("RRF_ALPHA",  ...,                    "float", 0.65, "advanced", "runtime", ...)
_p("RRF_K",      ...,                    "int",   4,    "advanced", "runtime", ...)
_p("BF_BOOST",   ...,                    "float", 0.06, "advanced", "runtime", ...)
_p("CHUNK_SIZE", "조각 크기 상한",        "int",   800,  "rebuild",  "rebuild", ...)
_p("embedModel", "임베딩 모델",           "text",  "dragonkue/BGE-m3-ko", "locked", "rebuild", ...)
_p("linkRoute",  "타기관 연락처 안내",     "bool",  True, "normal",   "runtime", ...)   # ④용 토글
```

**따라서 ③은 "변수 선언"이 아니라 "배선(wiring)" 작업이다.**
ver3 기준으로 `chatbot/`·`crawler/`는 admin settings를 **아무도 import하지 않는다.**
ver4 §3-7이 같은 진단에 독립적으로 도달했다 — *"`app.py`에 설정 주입 코드가 한 곳도 없어서
파라미터 7종 전부가 모듈 기본값에 묶여 있었다."* **배선 누락은 실재한다.**
→ ver4가 이미 배선했다면 M3은 **검증·확장**이고, 안 됐으면 **신규 구현**이다. M-1에서 판정.

### 0-6. 값의 두 종류 — 선언할 것과 측정할 것

| 종류 | 예 | 어디에 | 규칙 |
|---|---|---|---|
| **가변 파라미터** (우리가 정함) | k · RRF_ALPHA · CHUNK_SIZE | `admin/registry.py` | 선언 + 콘솔 노출 |
| **파생 사실** (파이프라인 결과) | **청크 수** · EMB_DIM · 인덱스 크기 | `settings.record_measured()` | **선언 금지.** 매번 `len()`으로 읽고 기록 |

**청크 개수를 상수로 박으면 안 된다.** 검증 #6이 "FAISS 적재 수 = 임베딩 수 = 메타 수 = 청크 수
대조"인데, 상수로 선언하면 그 대조가 **자기 자신과 비교**하는 셈이다. 179개가 적재됐는데
상수가 181이면 조용히 통과한다. 같은 원칙이 코드에 이미 있다 —
`EMB_DIM = 1024  # 모델 교체 시 갱신. build 시 실제 임베딩 차원으로 자동 보정됨`.

### 0-7. 단일 파일이 못 푸는 문제 — 파라미터·코퍼스 커플링

변수를 한 곳에 모아도 **"이 파라미터 세트가 이 코퍼스용인지"**는 알 수 없다.
필요한 것은 **지문 검사**다: 파라미터 세트에 코퍼스 `content_hash`/청크 수를 붙여두고
불일치 시 경고. `settings.mark_dirty(reason)`·`golden_diff()`가 이미 그 자리이므로,
**코퍼스 지문 불일치를 dirty 사유에 추가**한다. 이것이 §0-4 재발 방지 장치다.

> 관리자 UI에서 크롤링·재청킹이 계속 일어난다. **재청킹은 일회성 사고가 아니라 상수다.**
> 이 전제가 아래 두 가지를 결정한다.
>
> 1. **청크 ID를 손으로 고치는 작업(구 rev.2의 2A-3)은 폐기한다.** 다음 재청킹에 또 깨지는
>    일회용 작업이다. 대신 **근거 표기 자체를 청킹 비의존으로 전환**한다(2A-2).
> 2. **기준 스냅샷이 필요해진다.** 코퍼스가 움직이면 "무회귀"의 비교 대상이 사라진다(2A-4).

| 2A-1 | `verify_combos.py`에 **"참조 근거가 현행 코퍼스에 실존하는가"** 검사 추가 | dangling이 **적색으로** 뜬다 (지금은 조용히 통과) |

기준선의 코퍼스가 고정돼 있을 때만 성립하는 문장이다. 코퍼스가 상시 갱신되는 환경에서는

### ⚠️ 함정 — 이미 문서화된 것

`admin/runner.py`의 `apply_search_settings()`는 rag 모듈 속성을 주입하는데,

## 7. 부스트·top-k 유효성에 대한 서술 원칙 (오라클 실험 미실시)

**오라클 실험은 하지 않는다.** 다만 실험 없이도 확정된 구조적 사실이 있고,

전부 같은 문서 하나**(`MsdrprPossDcmntGudn`)를 가리킨다.

이는 데이터 구조의 결과이고, 08-06 문서 §5-c에서 이미 지적됐다("대리인 7종이 문서 하나에
