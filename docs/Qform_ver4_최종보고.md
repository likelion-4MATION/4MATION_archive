## §0. 이 스프린트가 한 것 / 하지 않은 것

### 한 것

큐폼(구조화 되묻기 층)을 **착오송금 1업무에서 예금보험금까지** 넓히는 재료를 만들고,
멀티턴 맥락을 **사용자가 보고 고치는 패널**로 꺼냈다.

| 축 | 결과 |
|---|---|
| **B유형 확장** | 예금보험금 조합 테이블 `DPIN-C01~C09` 9행 신설 (착오송금 14행은 **무변경**) |
| **D유형 용어사전** | 지급금 5종 + 채무조정 5종 = 10종. `one_line`·`discriminator` 전건 코퍼스 축자 |
| **멀티턴 패널** | 3구역(`적용 중`/`기억만 함`/`대기 중인 용건`) · X/pass 역할 분리 · TTL=3 · 다중의도 큐 |
| **자연어 입구** | 추출 스코프 파라미터화 + `보험금신청` 규칙 신설. **전환은 보류**(§3 H39) |

### ❌ 하지 않은 것 — **성능 개선을 주장하지 않는다 (K8)**

> "큐폼 확장으로 검색 성능이 올랐다"는 **주장하지 않으므로 재지 않았다.**
> 잰 것은 **"확장이 기존 동작을 망가뜨리지 않았다"** 하나다. **무해 증명이지 개선 주장이 아니다.**

- 쿼리 부스트 **기본 OFF 유지** (G13 미해결 · `rag.py` 동결)
- 되묻기 발동률을 **최적화 목표로 쓰지 않았다** (K12-2)
- D 되묻기 **미구현** (M1 판정 1 — `되묻기 필요` 0건이 근거)
- 동결 8종 **한 줄도 안 고쳤다**

## §5-3. ⚠ M2~M6 문서의 "검증 N종 exit 0" 을 그대로 믿지 마라 (H40)

**무엇이 무효인가.** M2~M6 보고서와 대화 보고에 적힌 **"검증 N종 exit 0"** 주장은 **무효다.**
그 측정에 쓴 셸 루프가

```bash
printf "%-30s exit=%s
" "$(basename $s)" "$?"      # ✗
```

형태였고, 셸이 `$(basename …)` 를 **먼저 실행**하면서 `$?` 를 basename 의 종료코드(**항상 0**)로
덮었다. **파이썬 스크립트가 실패해도 `exit=0` 으로 찍혔다.**

**무엇이 유효한가.** 같이 병기한 **stdout 지문은 유효하다** — 스크립트 표준출력에서 직접 grep 한 값이라
루프 버그의 영향을 받지 않는다:

| 유효 | 예 |
|---|---|
| `전체 통과 ✅` / `어긋난 AC ⛔` 문구 | 각 스크립트 말미 |
| `24/24` · `11/11` 통과 수 | 하니스 |
| 결과 지문 sha256 | `246d07124d333c9b` · `12619f9c100feb6e` |
| `전체 450: 9건 발동 (2.0%)` | `qform_state.py` AC4 |
| 조합 행수·조인 합계 | `verify_combos.py` |

**어떻게 드러났나.** M7 에서 `QFORM_SCOPE` 를 전환하자 `verify_qform_e2e.py` 가 실제로 exit 1 인데
루프는 0 을 찍었다. 루프를 고쳐 재측정하다 발견했다.

**유효 기준선은 M7 재측정치다.** §2-2 의 값은 아래 형태로 **전건 재측정**한 것이다:

```bash
n=$(basename "$s"); python3 "$s" >/dev/null 2>&1; rc=$?
```

→ `crawler/HOLES.md` **H40** · `CLAUDE.md` §5 에 확인법 명문화.

## §5-5. app.py 반영 점검 (M8-b)

`verify_qform_panel.py` 는 `panel_model`/`apply` **순수 함수**를 검증하지 Streamlit 렌더를 검증하지 않는다.
