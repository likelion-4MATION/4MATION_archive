착수 전 반드시 읽는다. T4가 이것을 스펙에 반영한다.

| # | 결정 | 영향 |
|---|---|---|
| **D1** | **게이트 폐기.** 큐폼 = "슬롯 추출기 + 조건부 되묻기". 모든 질의에 추출기를 돌린다 | 기획서 v1 §4·§5 전제 무효 · R4 폐기 |

### T2 — 결정론 슬롯 추출기

**파일** `chatbot/qform_extract.py` (신규)

**인터페이스**

```python
def extract(query: str, business_function: str | None = None) -> dict:
    """자연어 → 슬롯. LLM 호출 0. 못 잡으면 해당 키를 None으로 둔다.
    반환: {"party":…, "sub_task":…, "qualification":…, "subject":…, "method":…,
           "_hits": {슬롯: [매칭된 키워드]}}   # _hits는 커버리지 측정·디버깅용
    """
```

**설계 제약**

- **`sub_task` 우선.** 값별 어휘가 좁고 뚜렷하다 — "철회/취소", "해제", "계좌 바꾸/변경", "대리인 바꾸", "이의", "수수료 환급", "제도/뭔가요/란"
- **추출 실패는 정상.** 억지 매칭보다 `None`이 낫다 (오추출이 정답 조합을 지운다 — 기획서 §7)
- `business_function`은 MOAI 라우터가 프리필하므로 인자로 받는다. 없으면 `crawler/rag.py: classify_query_bf()` 사용 가능 (결정론)
- 값 표기는 조합 테이블/태깅 CSV와 **정확히 일치**해야 조인된다 ("신청" ✗ → "반환신청" ✓)

- [ ] LLM 호출 0 (grep으로 확인 가능)

### T3 — 조합 조회 + 되묻기 로직

**파일** `chatbot/qform_state.py` (신규)

**인터페이스**

```python
def next_question(slots: dict) -> dict | None:
    """되묻기 판정. None이면 되묻지 않고 바로 검색.
    반환: {"slot": "qualification", "examples": [...], "remaining": 7}
    """

def serialize(slots: dict) -> str:
    """슬롯 → 검색 쿼리에 덧붙일 문자열."""
```

**되묻기 규칙 (D2)**

```
sub_task is None            → None 반환 (되묻지 않음)  ← 오발동 방지의 핵심
survivors 수 <= 1           → None 반환
그 외                        → 남은 행을 가장 고르게 쪼개는 슬롯을 물음
최대 2턴. 2턴 후에도 미채움이면 None으로 진행
```

되묻기 문구는 **선택지 나열이 아니라 예시 제시**형: `"어떤 경우이신가요? (예: 본인 신청, 대리인 신청)"`

**수용 기준**

- [ ] 14행 기준 되묻기 시뮬레이션 출력 — 예상치: **0턴 7행 / 1턴 1행 / 2턴 6행, 평균 0.93턴**과 일치
- [ ] `sub_task=None`인 입력에서 `next_question()`이 항상 `None`
- [ ] `method`는 어떤 경로에서도 되묻지 않음
- [ ] 450셋 돌려 **되묻기 발동률** 출력 (= 오발동 지표. 낮을수록 정상)

## 3. 통합 지점 — 착수 전 확인 필요

### 3-1. `attachments.collect()` 와의 중복

`chatbot/attachments.py: collect(hits, doc_attachments)`는 **검색된 문서의 첨부를 전부 붙인다.** 그런데 `MsdrprPossDcmntGudn` 한 문서에 첨부가 **22건**이다. 이 문서가 hit되면 현재 로직은 22건을 다 반환한다.

조합 조인을 쓰면 **4~6건으로 좁혀진다.** 이게 큐폼의 정량화 가능한 값어치 중 하나다.

**결정 필요**: `collect()`를 대체할지, 조합 조인을 후단 필터로 얹을지. 후자가 안전하다 — 슬롯이 비면 기존 동작으로 자연히 되돌아간다(graceful degradation).

**측정 권장**: 착오송금 질의에서 `collect()` 단독 반환 건수 vs 조합 조인 후 건수. 이 감소폭이 발표 자료에 쓸 수치다.

### 3-2. `classify()` 와의 관계

`chain.py: classify()`는 HCX 호출 기반이고 `rag.py: classify_query_bf()`는 결정론이다. **슬롯 추출기는 이 둘과 별개 층**이다 — `classify`는 rag/reject 라우팅, 추출기는 슬롯 채움. 중복 호출이 생기지 않도록 호출 순서를 정리한다.
