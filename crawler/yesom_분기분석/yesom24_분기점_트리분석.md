## 0. 핵심 요약: 챗봇의 분기 동작 방식

예솜24는 **버튼 클릭식 대화 분기가 아니라, 질문을 의미검색해 특정 노드로 이동한 뒤 "관련 칩(chip)"으로 하위 분기를 제시**하는 방식이다. 즉 챗봇이 응답 말미에 보여주는 칩들이 곧 그 노드의 **자식 분기점**이다.

정확한 답변 생성을 위해 알아야 할 3가지 분기 축:

| 축 | 정의 | 값(예) |
|---|---|---|
| ① 업무적 분기 | 업무의 세부 갈래 | 안내/종류/신청, 이의제기/환급, 신고방법 등 |
| ② 자격 분기 | 신청 자격 | **본인 ↔ 대리인** |
| ③ 주체(주어) 분기 | 신청 주체(누가) | 예금자 본인 · 대리인 · 미성년자(→친권자) · 군인/군복무자 · 사망 예금자 · 국외거주/유학생 · 법인·단체(→대표/직원) · 비법인단체(→대표/직원) |

추가로 대부분 업무에 **신청수단 분기**(인터넷 / 방문 / 우편 / 이메일)가 존재한다.

| 축 | 정의 | 값(예) |
|---|---|---|
| ④ 조건 분기 | 절차가 아닌 **적격·판정 조건** | 대상금액·신청기한·제외사유·상계·종류·신고자격 등 (→ 8절) |

**2계층 구조 요약**: 모든 업무는 `[구조 분기: 업무·자격·주체·수단]`(1~3절 트리) + `[조건 분기: 적격·금액·기한·상계·종류 등]`(8절)의 2계층으로 나뉜다. 트리(1~6절)는 구조 분기를, 8절은 각 업무의 조건 분기를 다룬다.

## 1. 착오송금 반환 신청 (분기 최다)

```
착오송금 반환 신청
├─ [주체 분기] 착오송금인(송금인·보낸 사람)          ← "보낸 사람 반환" 질문 시 진입
│   └─ [수단 분기] { 인터넷 신청 · 방문 신청 · 신청 서류 }
│        └─ [자격 분기] 본인 ↔ 대리인
│             └─ [주체 분기] 대리인일 때:
│                  ├─ 미성년자
│                  ├─ 군복무자
│                  ├─ 국외거주 또는 유학생
│                  ├─ 법인 및 단체 대표
│                  ├─ 법인 및 단체 직원
│                  ├─ 비법인단체 대표
│                  └─ 비법인단체 직원
├─ [주체 분기] 착오송금수취인(수신인·잘못 받은 사람)
│   ├─ 이의제기       └─ [수단] 인터넷 / 방문
│   └─ 이체수수료 환급 └─ [수단] 인터넷 / 방문
└─ 착오송금반환지원 절차
```

**실측 근거**
- "착오송금을 보낸 사람인데 반환받고 싶어요" → *"착오송금인은 인터넷 또는 방문하여 신청할 수 있습니다."* 칩: `인터넷 신청` `방문 신청` `신청 서류`
- "착오송금 대리인이 신청할 때 서류" → *"대리인을 선택해주세요."* 칩 7종(미성년자/군복무자/국외거주·유학생/법인대표/법인직원/비법인대표/비법인직원)
- "착오송금 수취인 이의제기" / "이체수수료 환급" → 각각 인터넷 절차 안내 + `착오송금반환 신청 홈페이지` 칩

## 7. 정확한 답변 생성을 위한 핵심 인사이트 (실패/재검색 로그)

챗봇은 노드가 존재해도 **표현이 다르면 실패**한다("질문하신 의도가 명확하지 않아요"). 이것이 답변 정확도의 최대 병목이며, 학습·라우팅 시 **표현 동의어 매핑**이 필요하다.

| 실패한 질문(표현) | 결과 | 성공한 재검색 표현 |
|---|---|---|
| 은닉재산 이메일 신고 | 실패 | "은닉재산 어떻게 신고하나요" → 수단 분기 노출 |
| 채무조정 금액 | 실패 | "채무 조정이란?" → 진입 후 칩으로 이동 |
| 채무조정 신청 불가 사유 | 실패 | "채무 조정 신청 불가능한 경우는?" (챗봇이 직접 제안한 문구) |
| 착오송금 잘못 받은 수취인(막연) | 정의만 반환 | "착오송금 수취인 이의제기" / "이체수수료 환급" |

**시사점**
1. **진입 노드는 "○○이란?/○○ 안내" 형태**를 선호 → 상위 개념어로 진입 후 칩(자식 분기)으로 내려가는 구조.
2. 챗봇 실패 시 **재질문 제안 문구가 곧 정답 노드의 표준 표현** → 동의어 사전 구축에 활용 가능.
3. **주체(대리인 하위)·수단 분기는 명시적 칩 메뉴**로 제공되므로, 답변 라우팅 시 "본인/대리인 + 주체 + 수단"의 3중 슬롯을 채워야 리프(정답 서류)에 도달.
4. 리프 노드 답변에는 **양식 파일 다운로드 링크**가 함께 제공됨(신청서·위임장·동의서 등).

## 8. 조건 분기 확장 (재점검 결과)

1~6절 트리는 신청 절차의 **구조 분기(주체·자격·수단)** 다. 그런데 각 업무에는 절차와 무관한 **조건/적격 분기**가 별도로 존재하며, 이는 챗봇 상단 칩 메뉴에 노출되지 않고 자연어 질의로만 도달한다. 6개 업무를 FAQ 청크 + 라이브 챗봇으로 재점검한 결과다.

### 8-1. 착오송금 반환 신청 — `[대상 적격]` 축
- **대상 금액**: 5만원 이상 ~ 1억원 이하 (시행일별 상이: '21.7.6~ 1천만원, '23.1.1~·'25.1.1~ 1억원), 소급 적용 불가
- **신청 기한**: 착오송금일로부터 **1년 이내**
- **제외 사유**: 보이스피싱(전기통신금융사기 특별법으로 처리 → 대상 아님)
- **송금수단 조건**: 계좌번호 송금 O / 토스 등 연락처 송금 X(실지명의 확보 불가)
- (구조 분기의 사후관리 4종: 철회·매입계약해제·수령계좌변경·대리인변경 — 1절 참조. 챗봇 미노출)

### 8-2. 예금보험금 안내 — `[종류]` + `[상계 조건]` 축
- **종류 정의(각각 별개 노드)**: 예금보험금 / 가지급금 / 개산지급금 / 파산배당금 / 개산지급금정산금
- **예금+대출 동시보유**: 예금잔액에서 대출금 공제 후 지급(상계)
- **보증채무 보유**: 보증채무 해소 후 신청 가능
- **사망**: 상속인이 방문 신청

### 8-3. 고객 미수령금 신청 — `[종류]` + `[신청기간]` 축  ⚠️ 데이터 격차 최대
- **종류**: 예금보험금 / 파산배당금 / 개산지급금 정산금 (칩 분기)
- **신청기간(소멸시효, 종류별 상이)**: 가지급금·개산지급금=지급 종료일까지 / 보험금=지급개시일부터 5년 / 배당금·개산지급금정산금=통산 10년
- ※ `chunks.jsonl`에 미수령금 FAQ가 **0건** → 챗봇엔 있으나 크롤 데이터엔 없음. FAQ 크롤 보강 필요.

### 8-4. 은닉재산 신고 — `[신고자격/방식]` 축
- **신고방식**: 실명 원칙 / 익명·가명 신고 가능하나 **포상금 미지급**
- **신고자격**: 제한 없음 — 재외국민·외국인도 가능(포상 기준 동일)
- **대상 금액**: 제한 없음(금액 무관 신고 가능)
- **정의 노드**: 부실관련자 / 은닉재산

### 8-5. 채무조정 안내 — `[사후관리]` 축
- 기존(금액/확인방법/불가사유/서류)에 더해 **사후 재산조사**(도덕적 해이 방지, 연 1회 이상) 노드 존재

### 8-6. 예금자보호제도 — `[예금자유형/상품/한도조건]` 축
- **예금자 유형**: 개인 / 법인(규모 무관 1억, 단 정부·지자체·한은·금감원·예보·부보금융회사 제외)
- **상품별 별도한도**: 일반예금 1억 / 퇴직연금(DC·IRP·중퇴기금)·연금저축·사고보험금 = 별도 1억
- **명의 분산**: 가족·미성년자 명의별 각각 1억(실명확인 조건)
- **회사 합산**: 계열 저축은행도 법인이 다르면 각각 1억
- **상품 특성**: 외화예금 / 보험 해약환급금 / 원금+이자 합산

### 8-7. 챗봇 라우팅 실패 = RAG 커버 기회

FAQ 데이터엔 답이 있으나 라이브 챗봇이 "질문 의도가 명확하지 않아요"로 실패한 지점. RAG가 이 부분을 커버하면 즉시 우위.

| 업무 | 실패 질문(표현) | 비고 |
|---|---|---|
| 예금자보호 | 한 회사 여러계좌 합산 · 예금+대출 상계 · 세전/세후 | FAQ엔 존재, 챗봇 노드 라우팅 실패 |
| 채무조정 | "채무조정 신청 대상자는?" | 재질문 유도(불가사유로 우회) |
| 채무조정 | 인증서 오류·PC포맷·서비스시간 등 | 기술성 FAQ, 노드화 안 됨 |

### 8-8. 태깅 반영 권고
- 태깅 스키마/청크에 **`condition` 축**(또는 현재 비어있는 `variant` 필드)을 신설해 위 조건 분기를 담을 것.
- 조건 분기는 서식 첨부와 무관한 경우가 많으므로 **Tier A(검색대상 산문)** 로 인덱싱.
- 우선순위: ① 미수령금 FAQ 크롤 보강 ② 예금자보호·채무조정 실패 질문 노드 신설.
