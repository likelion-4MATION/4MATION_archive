# 첨부문서 태깅 스키마 & 분류 방법 (RAG용)

- 대상: KDIC 크롤링 첨부 46건 → **중복제거 26건(canonical)**
- 산출물: `attachment_tagging_template.csv` (사람이 검증·수정할 채움용 템플릿, 제안값 프리필) + 동일 내용 `.json`
- 태깅 정책: **다중라벨**(한 첨부가 여러 주체/수단에 해당). 반환 결정은 챗봇의 structured-output 질의분류가 담당하므로, 본 문서는 **첨부의 분기 좌표 분류**에만 집중.
- 작성일: 2026-08-03

---

## 1. 왜 이 스키마인가 (핵심 설계 판단)

크롤링된 첨부는 **거의 전부 빈 서식(양식) 파일**이라 내용 임베딩이 무의미하다. 그래서 첨부는 "검색 청크"가 아니라 **분기 좌표로 태깅된 반환 후보**로 다룬다. 질문이 (업무·주체·수단) 좌표로 분류되면, 같은 좌표를 가진 첨부를 조인해 반환하는 구조다.

또한 크롤 단위가 **페이지**라, 한 페이지(예: 착오송금인)에 서로 다른 주체·하위업무 서식이 통째로 섞여 있다. 그래서 페이지 링크를 실제로 열어 각 서식이 표의 어느 행(본인/대리인/미성년자/철회/…)에 속하는지 확인해 **페이지 단위 → 분기 단위로 재좌표화**했다.

## 2. 필드 정의 (CSV 열)

| 필드 | 타입 | 허용값 | 설명 |
|---|---|---|---|
| `attachment_id` | 단일 | ATT-01… | canonical 첨부 고유 ID |
| `source_doc_id` | 단일 | parent_doc_id | 출처 페이지(크롤 문서) |
| `business_function` | 단일 | 착오송금 반환 신청 / 예금보험금 안내 / 예금자보호제도 / 채무조정 안내 | 상위 업무 |
| `party` | 단일 | 송금인 / 수취인 / (공란) | **착오송금 전용** 최상위 분기 |
| `sub_task` | 단일 | 반환신청·이의제기·이체수수료환급·신청철회·매입계약해제·수령계좌변경·대리인변경·보험금신청·부보금융회사조회·부채증명 | 업무 내 세부 갈래 |
| `qualification` | **다중(;)** | 본인 / 대리인 | 자격 |
| `subject` | **다중(;)** | 본인·대리인·미성년자·군복무자·사망 예금자·국외거주 또는 유학생·법인·비법인단체·**공통** | 주체(주어). `공통`=전체 주체 와일드카드 |
| `method` | **다중(;)** | 온라인 / 방문 / 우편 / 이메일 | 신청 수단 |
| `doc_kind` | 단일 | 양식(빈서식) / 기재예시(샘플) / 안내자료 / 목록·표 | 문서 성격 |
| `form_type` | 단일 | 신청서·위임장·동의서·합의서·약정서·이의제기서·환급신청서·철회서·해제신청서·변경신청서·통지서·증명원신청서·목록 | 서식 종류 |
| `node_tag` | 단일 | 예솜 리프 `#태그` | 챗봇 시나리오 노드 연결(있을 때) |
| `retrieval_tier` | 단일 | A / B | **A=검색대상(임베딩)**, **B=첨부반환(메타조인)** |
| `available_formats` | 다중(;) | hwp;pdf;… | 보유 포맷 |
| `confidence(제안)` | 단일 | high/med/low | 제안 신뢰도 |
| `verified(사람입력)` | 단일 | (빈칸) | 검증 시 O/X 입력 |
| `corrected_tags(사람입력)` | 다중 | (빈칸) | 수정할 좌표 입력 |

## 3. 다중라벨 & '공통' 처리 규칙

- **공통 서식**(예: `신청서양식`, `금융거래정보제공동의서`, `채권양도통지위임장`)은 본인·대리인·미성년자 등 모든 주체가 제출한다. → `subject = 공통` 한 토큰으로 표기하고, 스키마상 **"공통은 모든 subject 질의에 매칭"** 으로 해석한다. (주체를 일일이 나열하지 않아 유지보수가 쉽다.)
- **주체 전용 서식**은 해당 주체만 표기: `친권합의서 → 미성년자`, `위임해지통지서 → 대리인`.
- 자격·수단도 같은 규칙: 온라인·방문 양쪽 제출 가능하면 `method = 온라인;방문`.
- 검색 매칭 시 규칙: **질문 좌표의 subject가 특정값이면 `subject∈{그 값, 공통}` 인 첨부를 모두 후보**로. (공통은 항상 포함)

---

## 4. Tier A vs Tier B (검색 vs 반환)

- **Tier B (24건)** — 빈 서식/샘플. 임베딩하지 말고 위 좌표로만 조인해 반환.
- **Tier A (2건)** — `부보금융회사 목록/변동현황`. 서식이 아니라 **자주 갱신되는 표 데이터**다. 행 단위(금융회사명 키)로 파싱해 검색대상에 넣고, 별도 갱신주기를 둔다.

---

## 5. 분류 결과 하이라이트 & 검증 필요 지점

- **착오송금 14건**이 가장 복잡: `송금인/수취인`(party) → `반환신청` 외에 **철회·매입계약해제·수령계좌변경·대리인변경** 4개 하위업무 서식이 같은 페이지에 존재. 이 4개는 **예솜 챗봇 분기에 노출되지 않은 숨은 분기**이므로 RAG에서 별도 노드로 신설 권장.
- **검증 필요(신뢰도 낮음) 2건**:
  - `지분신고서 및 수령권한 위임 동의서`(예금보험금) → 사망 예금자(공동상속 지분)로 추정 [med]
  - `손해담보 약정서`(예금보험금) → 상속 미확정/무증빙 담보로 추정 [low]
  - 두 건은 예금보험금 페이지의 `07 양식 다운로드` 아코디언에 주체 구분 없이 묶여 있어, 실제 상속 절차 문서로 최종 확인 필요.
- **크롤 누락 업무**: `고객 미수령금 신청`, `은닉재산 신고`는 이번 첨부 세트에 페이지가 없음 → 서식 반환이 필요하면 추가 크롤 필요.

## 6. 사람이 할 일 (템플릿 사용법)

1. `attachment_tagging_template.csv`를 열어 각 행의 제안 좌표를 확인.
2. 맞으면 `verified` 열에 `O`, 틀리면 `X` 후 `corrected_tags`에 올바른 값 기입.
3. `confidence=med/low` 행(2건)과 `notes`에 "검증필요" 표시된 행 우선 검토.
4. 확정본을 RAG 첨부 인덱스(structured-output 라우팅의 조인 테이블)로 적재.
